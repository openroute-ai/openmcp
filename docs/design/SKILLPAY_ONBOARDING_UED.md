## 1. 设计目标

1. **双轨同构**：个人（手机号验证）与 企业（企业认证 + 商户号绑定）共用一个入驻中心，步骤条按主体切换。
2. **结算前置可见**：把「已入驻 / 未入驻」做成一等公民状态，而不是藏在 payout 表单里。
3. **完成标志可验证**：每一步都有明确「完成标志」，企业轨附带三项完成检查清单。
4. **状态即页面**：`unverified / pending / verified / rejected / 结算未绑定` 五种状态各自有独立视图，不做半残态。
5. **门控一致**：免费发布不卡结算；付费发布（按次）必须 `bindStatus = bound`。

## 2. 与现状的差异

| 维度 | 现状（`PROVIDER_ONBOARDING_UED.md`） | 本设计 |
| --- | --- | --- |
| 步骤条 | 选主体 → 填资料 → 审核中 → 完成 | 选主体 → 资质验证 → **结算绑定** → 审核中 → 完成 |
| 个人资质 | 身份证 + 人脸核身 | 手机号验证码（可选保留证件） |
| 企业资质 | 营业执照 + 联系人 | 企业认证（含商户号绑定子步骤） |
| 结算 | `/provider/payout` 独立页，手填账户 / 二维码 | 集成为入驻 Step 3；原 payout 页保留为「修改结算信息」入口 |
| 结算状态 | `payChannelStatus: ready/…` | 增加 `bindStatus: unbound / pending / bound` + 商户号回执展示 |
| 成功页 | 分主体 CTA | 分主体 CTA + **三件事完成检查清单** |
| 发布门控 | `priceType` 未区分结算状态 | 付费发布需 `bindStatus='bound'` |

## 3. 信息架构与路由

```
/ provider
├── /provider/onboarding                 入驻中心（状态分发 + 步骤条）★ 本设计
│   ├── ?step=entity      Step 1 选主体
│   ├── ?step=identity    Step 2 资质验证（个人：手机号｜企业：企业认证）
│   ├── ?step=settlement  Step 3 结算绑定（企业必填，个人可跳过）
│   └── ?step=checklist   Step 4 完成检查
├── /provider/onboarding/individual      个人表单（保留独立路由，pending 时回跳）
├── /provider/onboarding/company         企业表单（同上）
└── /provider/payout                     结算信息维护（复用现有 ProviderPayoutForm）
```

侧边栏入口不变：**发布** 分组 → `入驻与收款` → `/provider/onboarding`。

```
                    ┌──────────────┐
      进入 ───────▶ │  未入驻       │ verificationStatus = null / unverified
                    └──────┬───────┘
                 选主体(Step1)
            ┌──────────────┴──────────────┐
            ▼                             ▼
   ┌────────────────┐            ┌────────────────────┐
   │ 个人：手机号验证 │            │ 企业：企业认证材料    │
   │ ✅ 直接进入结算  │            │ ⏳ pending 审核中    │
   └───────┬────────┘            └─────────┬──────────┘
           │                    ┌──────────┴──────────┐
           │                    ▼                     ▼
           │            ┌─────────────┐       ┌─────────────┐
           │            │ verified     │       │ rejected     │
           │            └──────┬──────┘       └──────┬──────┘
           │                   │                      │
           │            Step3 结算绑定                改资料重提
           │                   │                      │
           ▼                   ▼                      │
   ┌──────────────────────────────────┐               │
   │ 结算回执 bindStatus               │◀──────────────┘
   │  unbound ──▶ pending ──▶ bound    │
   └───────────────┬──────────────────┘
                   ▼
        ┌──────────────────────┐
        │ 完成（可发布）          │
        │ 免费：bindStatus 任意   │
        │ 付费：必须 bound        │
        └──────────────────────┘
```

### 4.1 状态 × 视图映射

| `verificationStatus` | `bindStatus` | 主视图 | 步骤条高亮 |
| --- | --- | --- | --- |
| `null` / `unverified` | — | 选主体卡片 | 选主体 |
| `pending` | — | **只读审核中**（琥珀横幅 + 已提交摘要 + 证件缩略图） | 审核中 |
| `verified` | `unbound` | 成功页 + **结算绑定提醒卡**（付费发布禁用） | 结算绑定 |
| `verified` | `pending` | 成功页 + 「绑定确认中」轮询条 | 结算绑定 |
| `verified` | `bound` | 成功页（完整 CTA）+ 完成检查清单 | 完成 |
| `rejected` | — | 错误横幅 + 审核备注 + 「修改资料重新提交」 | 资质验证 |

## 7. 文案表

| 场景 | 主文案 | 次文案 / 提示 |
| --- | --- | --- |

## 8. 交互与可访问性

1. 步骤条点击**仅可回退**到已完成步骤，前向跳转需完成当前校验。
2. 结算「刷新状态」为手动 + 每 10s 自动轮询（仅 `bindStatus='pending'` 时），切后台停止。
3. 只读态所有表单控件 `disabled` 且 `aria-disabled`，证件预览图 `alt` 含材料类型。
4. 二维码图片仅预览，不提供删除按钮（只读期）；维护期删除需二次确认。
5. 一键复制 Token / 商户号：复制成功按钮文案变「已复制」1.2s。
6. 敏感信息脱敏：证件号 `前3***后2`、Token 只展示一次、账号中间打码。

## 9. 门控矩阵（设计口径 · 已按新业务口径修订）

> 三层准入：`AUTH 登录` → `KYC 实名认证` → `OpenPay 收费入驻`。
> 完整矩阵与全站线框图见 [OPENPAY_SITE_UED.md](./OPENPAY_SITE_UED.md) §2.3。

| 动作 | 登录 | KYC（个人或企业） | OpenPay active | 备注 |
| --- | :---: | :---: | :---: | --- |
| 发布**免费** skills / MCP / A2A | ✅ | ✅ | — | 本次新口径：**个人也可发 MCP / A2A** |
| 发布**收费**资产（按次） | ✅ | ✅ | ✅ | 通道由主体决定 |
| 修改结算信息 | ✅ | ✅ | — | 降级为 OpenPay 的补充项 |
| 查看收益 / 申请提现 | ✅ | ✅ | ✅ | — |
| 升级为企业主体 | — | ✅ → pending | — | 期间不冻结已有 Skill |
| 调用收费接口（买家） | ✅ | — | — | 买家侧走 402 支付 |

**主体 → OpenPay 通道映射（不可手改）**

| 主体 | 通道 | 关键凭证 |
| --- | --- | --- |
| 个人 | 阿里云 AI 按量计费 | `serviceId` + 应用密钥 + 网关 |
| 企业 | 微信支付商家入驻（**平台为微信支付服务商**） | 子商户号 `mchid` + 下单能力 + 结算账户 |

> 本表取代原文中的 `bindStatus='bound'` / `payChannelStatus='ready'` 门控口径。
