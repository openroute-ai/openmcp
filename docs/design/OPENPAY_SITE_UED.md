## 0. 业务口径（本次锁定）

整个站点只分**两条业务线**，差别只在「准入门槛」：

| | 线路 A · 免费发布 | 线路 B · 收费发布（OpenPay） |
| --- | --- | --- |
| 目标 | 上传免费的 skills / MCP / A2A | 让资产按次收费，产生收益 |
| 准入链路 | **登录 → 个人/企业实名认证 → 发布** | **登录 → 实名认证 → OpenPay 入驻 → 发布** |
| 实名认证 | ✅ 必需 | ✅ 必需（入驻时一并完成） |
| OpenPay 入驻 | ❌ 不需要 | ✅ 必需 |
| 个人结算通道 | — | **阿里云 AI 按量计费**（服务注册 + 密钥 + `serviceId`） |
| 企业结算通道 | — | **微信支付商家入驻**（**平台为微信支付服务商**，进件生成子商户） |
| 结算 / 分成 | — | 个人：阿里云按量结算；企业：服务商分账到子商户 |
| 资产类型 | skills / MCP / A2A | skills / MCP / A2A |

### 0.1 三层准入模型

```
第 0 层  AUTH      登录（session）            —— 所有写操作
第 1 层  KYC       实名认证（个人 / 企业）       —— 发布任意资产（免费或收费）
第 2 层  OPENPAY   收费入驻（阿里云 / 微信服务商）—— 只有「收费」才需要
```

- **KYC 与 OpenPay 是两个独立状态**，不再合并成一个「入驻」按钮。
- OpenPay 入驻**前置依赖 KYC = verified**；KYC 未通过时 OpenPay 入口为禁用态并说明原因。
- 个人 KYC → 只能接 **阿里云 AI 按量计费**；企业 KYC → 只能接 **微信支付商家入驻（服务商）**。渠道由主体决定，不做自由选择（可扩展项见 [§9](#9-待确认项)）。

### 0.2 与旧口径的差异（需同步修订的既有设计）

| 项 | 旧口径 | 本次新口径 |
| --- | --- | --- |
| 发布 MCP / A2A | 仅企业主体（`PROVIDER_ONBOARDING_UED.md` Batch D 服务端门控） | **免费线：个人 / 企业实名后均可**（安全扫描门控不变） |
| 「入驻与收款」 | 一个入口混合实名 + 收款 | 拆成 **实名认证** 与 **OpenPay 收费入驻** 两张卡 |
| 收款绑定 | `/provider/payout` 手填账户 / 二维码 | 升级为 **OpenPay 通道接入**（阿里云 `serviceId` / 微信子商户号），原 payout 页保留为结算信息补充项 |
| 付费发布前置 | `payChannelStatus === 'ready'` | `openpayStatus === 'active'` |
| 站点入口 | OpenPay 仅营销页 | 首页、导航、Dashboard、发布页、详情页全部有分流与状态提示 |

## 2. 准入状态模型

### 2.1 状态机

```
 AUTH ──登录──▶ 未认证 ──────────────┐
                                    ▼
                        ┌──────────────────────┐
                        │ KYC 实名认证           │
                        │ unverified → pending  │
                        │   → verified / rejected│
                        └──────────┬───────────┘
                     verified      │
              ┌────────────────────┴───────────────────┐
              ▼                                        ▼
     线路 A · 免费发布                        线路 B · OpenPay 入驻
     （立即可用）                             openpayStatus:
                                             none → applying → pending
                                                    → active / suspended
                                                        │
                                    ┌───────────────────┴──────────────┐
                                    ▼                                  ▼
                          个人 KYC → 阿里云 AI 按量计费      企业 KYC → 微信支付商家入驻
                          serviceId + 密钥 + 签约            进件 → 子商户号 + 下单能力
                                    └───────────┬──────────────────────┘
                                                ▼
                                       可发布「收费」资产
                                       可查看收益 / 申请结算
```

### 2.2 字段口径（设计层，不落库）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `kycStatus` | `unverified / pending / verified / rejected` | 实名认证，沿用 `verificationStatus` |
| `entityType` | `individual / company` | 决定 OpenPay 可用通道 |
| `openpayStatus` | `none / applying / pending / active / suspended` | 收费入驻状态 |
| `openpayChannel` | `aliyun_aipay / wechat_mch` | 由 `entityType` 推导，不可手改 |
| `openpayAccount` | `{ externalId, displayName, boundAt, expiresAt }` | `externalId` = `serviceId` 或子商户号 |
| `payChannelStatus` | `ready / …` | 保留：结算信息（银行抬头等）是否齐备，**不再用于收费门控** |

### 2.3 门控矩阵

| 动作 | 登录 | KYC verified | OpenPay active |
| --- | :---: | :---: | :---: |
| 浏览 / 搜索 / 看详情 | — | — | — |
| 安装**免费**资产 | ✅ | — | — |
| 发布**免费** skills / MCP / A2A | ✅ | ✅ | — |
| 提交**收费**资产 / 填写单价 | ✅ | ✅ | ✅ |
| 查看收益与结算明细 | ✅ | ✅ | ✅ |
| 申请提现 / 打款 | ✅ | ✅ | ✅ |
| 调用收费接口（买家） | ✅ | — | —（买家侧走支付） |
| 管理端审核 | admin | — | — |

> **实现要点（对齐 `SKILLPAY_ONBOARDING_PLAN.md` §2.3）**：门控在**服务端**执行，前端只负责表达；免费资产的提交请求不读 `openpayStatus`，收费资产的提交请求强校验 `openpayStatus === 'active'`。

## 3. 全局组件

### 3.1 顶部导航

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [logo]  技能▾  插件  OpenPay  大赛  探索▾  使用指南     [ 登录 ] [ + 发布▾ ] │
│                                                    （已登录：头像▾）         │
├──────────────────────────────────────────────────────────────────────────────┤
│ 准入状态条（仅已登录且存在缺口时出现，可关闭，15s 后不再自动弹出）：             │
│ ⚠ 实名认证未完成 → 免费发布已锁定                         [ 去实名认证 ]       │
│ ⚠ OpenPay 未入驻 → 收费发布已锁定     （+ 完成实名后才显示这行）[ 去入驻 ]     │
└──────────────────────────────────────────────────────────────────────────────┘
```

- `+ 发布` 下拉按准入状态动态渲染：
  - 未登录 → `登录后发布`
  - KYC 未通过 → `发布免费资产`（置灰，副文案「需先实名认证」）+ `发布收费资产`（置灰）
  - KYC 通过、OpenPay 未入驻 → 免费项可用；收费项置灰 + `去 OpenPay 入驻`
  - 全部通过 → 三项全可用
