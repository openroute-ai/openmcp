          三件事要先分清：


          - key 的 `subscriptions:write` 管「能不能创建/管理订阅」；订阅自己的 `scopes`
          管「推什么」。投递时按订阅的 scope 读库，**不借用调用方 key 的权限**。

          - 这把 key 同时也是**签名 key**：验签密钥由它的 `key_hash` 派生（响应里的 `signingKey`），同 key
          名下所有订阅共用一个，不需要按订阅分发第二个凭据。

          - 过滤器不是白名单语义而是「先命中即短路」，规则见 §6.6。
