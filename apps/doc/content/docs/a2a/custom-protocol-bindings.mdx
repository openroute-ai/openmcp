---
title: '自定义协议绑定'
---

A2A 协议自带三种标准绑定（JSON-RPC、gRPC 和 HTTP+JSON/REST），覆盖了大多数部署场景。自定义协议绑定允许实现者通过标准集合未涵盖的额外传输机制来暴露 A2A 操作。

自定义协议绑定与[扩展](/docs/a2a/extensions)是互补但不同的概念。扩展通过在现有传输之上添加新的数据、方法或状态转换来修改协议交互的*行为*。自定义协议绑定则改变*传输层*本身——例如，通过 WebSockets 暴露 A2A 以实现低延迟的双向通信，或通过 MQTT 用于连接受限的 IoT 环境。

## 在 Agent Card 中声明

自定义协议绑定在 Agent Card 的 `supportedInterfaces` 列表中声明。每个条目通过 URI 标识传输方式、端点 URL，以及其实现的 A2A 协议版本。`protocolBinding` 字段应是一个能够唯一标识该绑定的 URI（规范性要求及版本控制指南请参阅[规范第 5.8 节](/docs/a2a/specification/index)）。

```json
  ]
}
```

支持多种绑定的智能体会全部列出。客户端按顺序解析 `supportedInterfaces`，并选择它们支持的第一个传输方式，因此条目应按偏好顺序排列。

## 要求

自定义协议绑定必须符合规范中[协议绑定要求与互操作性](/docs/a2a/specification/bindings)一节的全部要求。具体而言：

- **必须支持所有核心操作。** 绑定必须暴露抽象操作层定义的每个操作（发送消息、获取任务、取消任务、流式传输、推送通知等）。
- **必须保持数据模型。** 所有数据结构必须在功能上等同于规范的 Protocol Buffer 定义。JSON 序列化必须使用 camelCase 字段名，时间戳必须是在 UTC 下的 ISO 8601 字符串。
- **行为必须一致。** 无论使用哪种绑定，语义上等价的请求都必须产生语义上等价的结果。

## 需要明确的重点领域

自定义绑定规范必须涉及以下每个领域。

### 数据类型映射

记录每种 Protocol Buffer 类型在自定义传输中如何表示，包括：

- 二进制数据编码（例如，文本型传输使用 base64）
- 枚举表示（字符串、整数或命名常量）
- 时间戳格式（按照核心约定为 UTC 下的 ISO 8601 字符串）

### 服务参数

服务参数是用于承载横切上下文（如追踪标识符或认证提示）的键值对。绑定规范必须说明：

- 承载服务参数的机制（例如，自定义消息头、顶层元数据字段）
- 对键和值的任何字符编码或大小限制
- 由绑定本身保留的任何名称

对于缺乏原生头部支持的传输，一种常见做法是将服务参数作为 JSON 对象嵌入专用元数据字段中，例如 `a2a-service-parameters`。

### 错误映射

绑定必须将所有 A2A 错误类型映射为传输原生的错误表示，同时保留其语义含义。提供一张与规范中[错误码映射](/docs/a2a/specification/index)一节等价的映射表，说明每种 A2A 错误类型（例如 `TaskNotFoundError`、`UnsupportedOperationError`）如何以自定义绑定的原生错误格式表达。

### 流式

如果传输支持流式传输，请记录：

- 流机制（例如，WebSocket 帧、分块编码、长轮询）
- 顺序保证（事件必须按生成顺序投递）
- 连接中断时的重连行为
- 流的完成或终止如何传达给客户端

如果传输不支持流式传输，请在 Agent Card 中明确说明此限制，以便客户端回退到轮询。

### 认证与授权

记录 Agent Card 中声明的认证凭据如何通过自定义传输传递。定义认证质询如何传达给客户端，并确保自定义绑定不会无意中绕过智能体的主要安全控制。

## 互操作性测试

在发布自定义绑定之前，请验证：

- 对于相同的逻辑请求，所有操作的行为与标准绑定一致
- 错误条件、大载荷和长时间运行的任务得到正确处理
- 任何有意偏离标准绑定行为的地方都有明确的文档说明
- 规范中应包含示例请求和响应，以帮助实现者

## 治理

A2A 组织使用正式的治理框架来管理自定义协议绑定的提出、开发、推广和维护。官方绑定使用 `https://a2a-protocol.org/bindings/` URI 前缀，托管在 `a2aproject` 组织下，仓库名带有 `cpb-` 前缀（实验性绑定使用 `experimental-cpb-`）。A2A SDK 应当实现官方自定义协议绑定。

<Callout title="URI 命名空间">

`https://a2a-protocol.org/bindings/` 前缀是一个规范性的命名空间，用于在 Agent Card 中提供全局唯一的绑定标识符。该前缀下的各个 URI（例如 `https://a2a-protocol.org/bindings/{name}/v1`）标识特定的绑定及其版本。这些 URI 是标识符，不期望 HTTP 访问。详细信息请参阅治理文档中的 [URI 命名空间](/docs/a2a/extension-and-binding-governance)。


</Callout>
