title: 'A2A 与 MCP'
---

在 AI 智能体开发中，出现了两种促进互操作性的关键协议类型。一种将智能体连接到工具和资源。另一种则实现智能体之间的协作。Agent2Agent（A2A）协议和 [Model Context Protocol](https://modelcontextprotocol.io/)（MCP）解决了这些截然不同但又高度互补的需求。

## 水平层与垂直层

一种理解这两种协议的方式，是看它们连接的方向。

**MCP 是垂直的。** 它深化单个智能体。你可以在同一框架下构建一个智能体系统——在单个应用中包含一个或多个智能体。你添加的每个 MCP 连接都会让智能体掌握一个新的工具、资源或技能。连接得越多，那个智能体自身能做的事情就越多。

**A2A 是水平的。** 它在边界之上连接智能体。另一个智能体可能属于其他团队、其他部门或合作伙伴组织。你的智能体主动接触这些智能体，进行发现、协商和信息交换。

这种水平连接远远不止向另一个智能体询问状态更新。它更接近一个人向另一个人寻求帮助的方式：_"你在做这个项目吗？了解它吗？你能分享你掌握的信息吗——如果不能，哪个智能体可以？"_ 智能体打破僵局、交换上下文，并根据交流的进展——要么更深入一步，要么被指引到完成工作的更好去处。

两者结合使用，MCP 赋予每个智能体深度，A2A 则为你的系统带来广度。

## Model Context Protocol

Model Context Protocol（MCP）定义了 AI 智能体如何使用单个工具和资源，例如数据库或 API。

该协议提供以下能力：

- 标准化 AI 模型和智能体连接并交互工具、API 和其他外部资源的方式。
- 定义了一种描述工具能力的结构化方式，类似于大语言模型中的函数调用。
- 将输入传递给工具并接收结构化输出。
- 支持常见用例，例如 LLM 调用外部 API、智能体查询数据库，或智能体连接到预定义函数。

## Agent2Agent 协议

Agent2Agent 协议让不同的智能体协作，共同达成目标。

该协议提供以下能力：

- 标准化独立的、通常是不透明的（opaque）AI 智能体如何作为对等方进行通信和协作。
- 为智能体提供应用层协议。借助它，智能体能够相互发现并协商交互。它们还管理共享任务，并交换对话上下文和复杂数据。
- 支持常见用例。例如，客服智能体可以将咨询委托给计费智能体。旅行智能体可以协调航班、酒店和活动智能体。

## 为什么需要不同的协议？

两种协议对于构建复杂的 AI 系统都至关重要。A2A 与 MCP 的区别取决于智能体与之交互的对象。

- **工具和资源（MCP 领域）**：
      - **特性：** 这些通常是具有明确定义、结构化输入输出的原语。它们执行特定的、通常无状态的函数。示例包括计算器、数据库查询 API 或天气查询服务。
      - **用途：** 智能体使用工具来收集信息和执行离散函数。
- **智能体（A2A 领域）**：
      - **特性：** 这些是更自主的系统。它们会推理、规划并使用多种工具。它们在较长的交互中保持状态，并进行复杂的、通常多轮的对话，以处理新颖或不断演变的任务。
      - **用途：** 智能体与其他智能体协作，以应对更广泛、更复杂的目标。

## A2A ❤️ MCP：面向智能体系统的互补协议

一个智能体应用可以使用 A2A 与其他智能体通信。在其内部，每个智能体使用 MCP 与自己的工具和资源协同工作。

### 示例场景：汽车维修厂

设想一个汽车维修厂，由自主 AI 智能体"机修工"提供服务。这些机修工使用专用工具诊断和修复问题。它们的工具包括车辆诊断扫描仪、维修手册和举升平台。维修过程可能涉及长时间的对话、研究以及与零部件供应商的合作。

- **客户交互——通过 A2A 进行用户到智能体的交互。** 客户或其助手智能体会与"店长"智能体交流。

    例如，客户可能会说"我的车发出咔嗒咔嗒的响声"。

- **诊断对话——通过 A2A 进行智能体到智能体的交互。** 店长智能体会进行来回往复的诊断对话。

    例如，店长可能会问"你能发一段异响的视频吗？"或"我看到有液体泄漏。这种情况持续多久了？"。

- **内部工具使用——通过 MCP 进行智能体到工具的交互。** 被店长分配任务的机修工智能体需要诊断问题。它使用 MCP 访问其专用工具。

    例如：

    - MCP 调用"车辆诊断扫描仪"工具：
        `scan_vehicle_for_error_codes(vehicle_id='XYZ123')`
    - MCP 调用"维修手册数据库"工具：
        `get_repair_procedure(error_code='P0300', vehicle_make='Toyota',
        vehicle_model='Camry')`
    - MCP 调用"举升平台"工具：`raise_platform(height_meters=2)`

- **供应商交互——通过 A2A 进行智能体到智能体的交互。** 机修工智能体发现需要某个特定零件。它使用 A2A 与"零部件供应商"智能体沟通并订购该零件。
    例如，机修工智能体可能会问"你们有适用于 2018 款 Toyota Camry 的 #12345 零件库存吗？"

- **订单处理——通过 A2A 进行智能体到智能体的交互。** 零部件供应商智能体同样是一个兼容 A2A 的系统。它会做出响应，从而可能导致产生订单。

在此示例中：

- A2A 处理更高级别的、会话式的、面向任务的交互。它将客户与店方连接起来，并将店方智能体与外部供应商智能体连接起来。
- MCP 使机修工智能体能够使用其特定的、结构化的工具来执行诊断和维修功能。

## 将 A2A 智能体表示为 MCP 资源

A2A Server（远程智能体）可以将某些技能暴露为兼容 MCP 的资源。当这些技能定义良好且能够以类似工具的、无状态的方式调用时，效果最佳。另一个智能体随后可以通过 MCP 风格的工具描述"发现"该技能，该描述或许源自 Agent Card。

尽管如此，A2A 的主要优势在于它对灵活的、有状态的、协作式的交互的支持，这超越了典型的工具调用。A2A 关乎智能体在任务上 _携手合作_（partnering）；MCP 则更多关乎智能体 _使用_（using）能力。

将两者搭配使用。A2A 处理智能体间的协作，MCP 处理工具集成。这让你能够构建更强大、更灵活、更具互操作性的 AI 系统。
