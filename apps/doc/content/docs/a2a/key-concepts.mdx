A2A 使用一组核心概念来定义智能体如何交互。
理解这些核心构建块，以开发或集成符合 A2A 规范的系统。

<img src="/images/docs/a2a/a2a-actors.png" alt="A2A Actors showing a User, A2A Client (Client Agent), and A2A Server (Remote Agent)" width="1264" height="678" />

## A2A 交互中的核心参与者

- **用户（User）**：最终用户，可以是人类操作员或自动化服务。用户发起请求或定义一个需要由一个或多个 AI 智能体协助的目标。
- **A2A 客户端（客户端智能体）**：代表用户行事的应用、服务或另一个 AI 智能体。客户端使用 A2A 协议发起通信。
- **A2A 服务端（远程智能体）**：暴露实现 A2A 协议的 HTTP 端点的 AI 智能体或智能体系统。它从客户端接收请求、处理任务，并返回结果或状态更新。对客户端而言，远程智能体是一个 _不透明的_（黑盒）系统：其内部工作方式、记忆和工具都保持隐藏。

## 基本通信元素

下表描述了 A2A 中的基本通信元素：

| 元素 | 描述 | 核心用途 |
| :------ | :---------- | :---------- |
| Agent Card | 描述智能体的身份、能力、端点、技能和认证要求的 JSON 元数据文档。 | 使客户端能够发现智能体，并理解如何安全有效地与它们交互。 |
| 任务（Task） | 由智能体发起的有状态工作单元，具有唯一 ID 和定义的生命周期。 | 促进对长时间运行操作的跟踪，并支持多轮交互和协作。 |
| 消息（Message） | 客户端与智能体之间的一轮通信，包含内容和角色（"用户"或"智能体"）。 | 传达不一定是正式产物的指令、上下文、问题、答案或状态更新。 |
| 部件（Part） | 消息（Messages）和产物（Artifacts）中使用的基本内容容器。一个 Part 保存以下其中一项：文本内容、文件引用（URL 或内联字节）或结构化数据。 | 为智能体在消息和产物中交换各种内容类型提供了灵活性。 |
| 产物（Artifact） | 智能体在任务期间生成的有形输出（例如，文档、图像或结构化数据）。 | 交付智能体工作的具体结果，确保输出的结构化和可检索。 |

## 交互机制

A2A 协议支持多种交互模式。每种模式都适合对响应性和持久性的不同需求。凭借它们，无论任务的复杂程度或持续时间如何，智能体都能可靠地交换信息：

- **请求/响应（轮询）**：客户端发送请求，服务端响应。对于长时间运行的任务，客户端会定期轮询服务端以获取更新。
- **使用服务器发送事件（SSE）的流式**：客户端通过打开的 HTTP 连接建立流。它们接收服务端实时、增量的结果或状态更新。
- **推送通知**：服务端在任务有重大更新时调用客户端提供的 webhook。这适用于非常长时间运行的任务或处于断连状态的客户端。

有关流式和推送通知的更多信息，请参见
[流式与异步操作](/docs/a2a/streaming-and-async)。

## Agent Cards

Agent Card 是一个 JSON 文档。它充当数字名片。它提供用于初始发现和交互设置的关键元数据。客户端解析它来决定智能体是否适合某项任务、如何构造请求，以及如何安全地通信。卡片列出了身份、服务端点（URL）、A2A 能力、认证要求和技能。

## 消息与部件

消息表示客户端与智能体之间的一轮通信。它包含一个角色（"用户"或"智能体"）和一个唯一的 `messageId`。它包含一个或多个 Part 对象，这些对象是实际内容的细粒度容器。这种设计使 A2A 能够做到模态无关（modality independent）。

`Part` 对象是一个灵活的容器，可以使用 `oneof` 字段结构容纳不同类型的内容。一个 Part 必须恰好包含以下内容字段之一：

- `text`：包含纯文本内容的字符串。
- `raw`：包含二进制文件数据（内联）的字节数组。
- `url`：引用外部文件内容的字符串 URI。
- `data`：用于机器可读数据的结构化 JSON 值（例如，对象、数组）。

此外，每个 `Part` 还可以包含：

- `mediaType`：内容的 MIME 类型（例如，`"text/plain"`、`"image/png"`、`"application/json"`）。
- `filename`：文件或内容的可选名称。
- `metadata`：用于附加上下文的键值映射。

## 产物（Artifacts）

产物（artifact）是远程智能体在任务期间生成的有形输出或具体结果。与一般的消息不同，产物是实际的交付成果。一个产物具有唯一的 `artifactId`、可读的名称，以及一个或多个部件对象。产物与任务生命周期紧密相关，并且可以增量流式传输给客户端。

## 智能体响应：任务或消息

智能体响应可以是新的 `Task`（当智能体需要执行长时间运行的操作时）或 `Message`（当智能体可以立即响应时）。

更多详细信息，请参见 [任务的生命周期](/docs/a2a/life-of-a-task)。

## 其他重要概念

- **上下文（`contextId`）：** 服务端生成的标识符。使用它对相关的 `Task` 对象进行分组，并在一系列交互中携带上下文。
- **传输与格式：** A2A 通信通过 HTTP(S) 进行。JSON-RPC 2.0 用作所有请求和响应的载荷格式。
- **认证与授权：** A2A 依赖标准的 Web 安全实践。认证要求在 Agent Card 中声明，凭据（例如 OAuth 令牌、API 密钥）通常通过 HTTP 头部传递，与 A2A 协议消息本身分开。更多信息，请参见 [企业级特性](/docs/a2a/enterprise-ready)。
- **智能体发现：** 客户端查找 Agent Card 以了解可用 A2A Server 及其能力的过程。更多信息，请参见 [智能体发现](/docs/a2a/agent-discovery)。
- **扩展：** A2A 允许智能体将自定义协议扩展作为其 AgentCard 的一部分来声明。更多信息，请参见 [扩展](/docs/a2a/extensions)。
