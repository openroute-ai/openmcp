---
title: 理解 MCP 服务器
---


MCP 服务器是通过标准化的协议接口向 AI 应用暴露特定能力的程序。

常见的示例包括用于文档访问的文件系统服务器、用于数据查询的数据库服务器、用于代码管理的 GitHub 服务器、用于团队沟通的 Slack 服务器，以及用于日程安排的日历服务器。

## 核心服务器特性

服务器通过三个基础组件提供功能：

| 特性       | 说明                                                                                                                                                                                                 | 示例                                                                 | 控制者      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ----------- |
| **工具**     | 你的 LLM 可以主动调用的函数，它根据用户请求决定何时使用它们。工具可以写入数据库、调用外部 API、修改文件或触发其他逻辑。                                                                                      | 搜索航班<br />发送消息<br />创建日历事件                                  | 模型        |
| **资源**     | 提供只读访问上下文的被动数据源，例如文件内容、数据库模式或 API 文档。                                                                                                                                  | 检索文档<br />访问知识库<br />读取日历                                  | 应用        |
| **提示词**   | 预先构建的指令模板，告诉模型如何与特定的工具和资源配合使用。                                                                                                                                            | 规划假期<br />总结我的会议<br />起草邮件                                  | 用户        |

我们将用一个假想场景来演示这些特性的各自作用，并展示它们如何协同工作。

### 工具

工具让 AI 模型能够执行动作。每个工具都定义了一个具有类型化输入和输出的特定操作。模型根据上下文请求工具执行。

#### 工具如何工作

工具是 LLM 可以调用的、由模式定义的接口。MCP 使用 JSON Schema 进行校验。每个工具执行一个单一的操作，具有明确定义的输入和输出。工具在执行前可能需要用户同意，这有助于确保用户对模型所采取的动作保持控制。

**协议操作：**

| 方法       | 用途                  | 返回                                |
| ---------- | --------------------- | ----------------------------------- |
| `tools/list` | 发现可用工具          | 带有模式的工具定义数组              |
| `tools/call` | 执行特定的工具        | 工具执行结果                        |

**工具定义示例：**

```typescript
{
  name: "searchFlights",
  description: "Search for available flights",
  inputSchema: {
    type: "object",
    properties: {
      origin: { type: "string", description: "Departure city" },
      destination: { type: "string", description: "Arrival city" },
      date: { type: "string", format: "date", description: "Travel date" }
    },
    required: ["origin", "destination", "date"]
  }
}
```

#### 示例：旅行预订

工具让 AI 应用能够代表用户执行动作。在旅行规划场景中，AI 应用可能会使用多个工具来帮助预订假期：

**航班搜索**

```
searchFlights(origin: "NYC", destination: "Barcelona", date: "2024-06-15")
```

查询多个航空公司并返回结构化的航班选项。

**日历锁定**

```
createCalendarEvent(title: "Barcelona Trip", startDate: "2024-06-15", endDate: "2024-06-22")
```

在用户的日历中标记旅行日期。

**邮件通知**

```
sendEmail(to: "team@work.com", subject: "Out of Office", body: "...")
```

向同事发送自动化的"不在办公室"邮件。

#### 用户交互模型

工具由模型控制，这意味着 AI 模型可以自动发现并调用它们。不过，MCP 通过若干机制强调人工监督。

出于信任和安全考虑，应用可以通过各种机制实现用户控制，例如：

- 在 UI 中显示可用工具，让用户能够界定某个工具是否应在特定交互中可用
- 针对单次工具执行的审批对话框
- 预先批准某些安全操作的权限设置
- 显示所有工具执行及其结果的活动日志

### 资源

资源提供对信息的结构化访问，AI 应用可以检索这些信息并作为上下文提供给模型。

#### 资源如何工作

资源暴露来自文件、API、数据库或任何其他 AI 需要理解的上下文来源的数据。应用可以直接访问这些信息，并决定如何使用它——无论是用嵌入选取相关部分、进行搜索，还是把全部内容传给模型。

每个资源都有一个唯一的 URI（例如 `file:///path/to/document.md`），并声明其 MIME 类型以实现合适的内容处理。

资源支持两种发现模式：

- **直接资源** - 指向特定数据的固定 URI。示例：`calendar://events/2024` - 返回 2024 年的日历可用情况
- **资源模板** - 带有参数、用于灵活查询的动态 URI。示例：
  - `travel://activities/{city}/{category}` - 按城市和类别返回活动
  - `travel://activities/barcelona/museums` - 返回巴塞罗那的所有博物馆

资源模板包含标题、描述和预期 MIME 类型等元数据，使其可发现且自带文档。

**协议操作：**

| 方法                     | 用途                         | 返回                                    |
| ------------------------ | ---------------------------- | --------------------------------------- |
| `resources/list`         | 列出可用的直接资源           | 资源描述符数组                          |
| `resources/templates/list` | 发现资源模板                 | 资源模板定义数组                        |
| `resources/read`         | 检索资源内容                 | 带元数据的资源数据                      |
| `subscriptions/listen`   | 监控资源变化                 | 更新通知流                              |

要监听特定资源的变化，客户端会发送一个 [`subscriptions/listen`](/docs/mcp/specification/2026-07-28/basic/patterns/subscriptions) 请求，在 `resourceSubscriptions` 过滤器中列出资源 URI。每当所监听资源发生变化时，服务器会在由此产生的流上投递 `notifications/resources/updated`。

#### 示例：获取旅行规划的上下文

延续旅行规划的示例，资源为 AI 应用提供相关信息的访问：

- **日历数据** (`calendar://events/2024`) - 检查用户的可安排时间
- **旅行文档** (`file:///Documents/Travel/passport.pdf`) - 访问重要的文件
- **之前的行程** (`trips://history/barcelona-2023`) - 参考过去的旅行和偏好

AI 应用检索这些资源并决定如何处理它们，无论是用嵌入或关键词搜索选取数据的子集，还是把原始数据直接传给模型。

在本例中，它向模型提供日历数据、天气信息和旅行偏好，使其能够检查可安排时间、查询天气模式，并参考过去的旅行偏好。

**资源模板示例：**

```json
{
  "uriTemplate": "weather://forecast/{city}/{date}",
  "name": "weather-forecast",
  "title": "Weather Forecast",
  "description": "Get weather forecast for any city and date",
  "mimeType": "application/json"
}

{
  "uriTemplate": "travel://flights/{origin}/{destination}",
  "name": "flight-search",
  "title": "Flight Search",
  "description": "Search available flights between cities",
  "mimeType": "application/json"
}
```

这些模板支持灵活的查询。对于天气数据，用户可以访问任意城市/日期组合的天气预报。对于航班，他们可以搜索任意两个机场之间的航线。当用户把 `origin` 机场输入为 "NYC" 并开始输入 `destination` 机场为 "Bar" 时，系统可以建议"Barcelona (BCN)"或"Barbados (BGI)"。

#### 参数补全

动态资源支持参数补全。例如：

- 为 `weather://forecast/{city}` 输入 "Par" 可能会建议 "Paris" 或 "Park City"
- 为 `flights://search/{airport}` 输入 "JFK" 可能会建议 "JFK - John F. Kennedy International"

系统帮助用户发现合法的值，而不要求他们预先知道确切的格式。

#### 用户交互模型

资源由应用驱动，这给了它在检索、处理和呈现可用上下文方面的灵活性。常见的交互模式包括：

- 以熟悉的文件夹式结构浏览资源的树状或列表视图
- 用于查找特定资源的搜索与过滤界面
- 基于启发式规则或 AI 选择的自动上下文包含或智能建议
- 用于纳入单个或多个资源的手动或批量选择界面

应用可以自由地通过任何适合其需求的界面模式实现资源发现。协议不强求特定的 UI 模式，允许使用带预览功能的资源选择器、基于当前对话上下文的智能建议、用于纳入多个资源的批量选择，或与现有文件浏览器和数据探查器集成。

### 提示词

提示词提供可复用的模板。它们让 MCP 服务器作者能够为一个领域提供参数化的提示词，或展示如何最好地使用该 MCP 服务器。

#### 提示词如何工作

提示词是定义预期输入和交互模式的结构化模板。它们由用户控制，需要显式调用，而不是自动触发。提示词可以感知上下文，引用可用的资源和工具来创建综合性的工作流。与资源类似，提示词支持参数补全，帮助用户发现合法的参数值。

**协议操作：**

| 方法         | 用途                    | 返回                               |
| ------------ | ----------------------- | ---------------------------------- |
| `prompts/list` | 发现可用的提示词        | 提示词描述符数组                   |
| `prompts/get`  | 检索提示词详情          | 带参数的完整提示词定义             |

#### 示例：简化工作流

提示词为常见任务提供结构化模板。在旅行规划的场景中：

**"规划假期"提示词：**

```json
{
  "name": "plan-vacation",
  "title": "Plan a vacation",
  "description": "Guide through vacation planning process",
  "arguments": [
    { "name": "destination", "type": "string", "required": true },
    { "name": "duration", "type": "number", "description": "days" },
    { "name": "budget", "type": "number", "required": false },
    { "name": "interests", "type": "array", "items": { "type": "string" } }
  ]
}
```

相比非结构化的自然语言输入，提示词系统实现了：

1. 选择"规划假期"模板
2. 结构化输入：巴塞罗那、7 天、3000 美元、["海滩"、"建筑"、"美食"]
3. 基于模板的一致工作流执行

#### 用户交互模型

提示词由用户控制，需要显式调用。协议给了实现者自由，让他们可以设计在自身应用中感觉自然的界面。关键原则包括：

- 轻松发现可用的提示词
- 清晰描述每个提示词的作用
- 带校验的自然参数输入
- 透明地展示提示词背后的模板

应用通常通过各种 UI 模式暴露提示词，例如：

- 斜杠命令（输入"/"来查看可用的提示词，如 /plan-vacation）
- 可搜索访问的命令面板
- 针对常用提示词的专用 UI 按钮
- 建议相关提示词的上下文菜单

## 将服务器整合起来

当多个服务器协同工作时，通过统一的界面组合各自的专门能力，MCP 的真正威力才会显现。

### 示例：多服务器旅行规划

设想一个个性化的 AI 旅行规划器应用，它连接了三个服务器：

- **旅行服务器** - 处理航班、酒店和行程
- **天气服务器** - 提供气候数据和预报
- **日历/邮件服务器** - 管理日程和通信

#### 完整流程

1. **用户以参数调用提示词：**

   ```json
   {
     "prompt": "plan-vacation",
     "arguments": {
       "destination": "Barcelona",
       "departure_date": "2024-06-15",
       "return_date": "2024-06-22",
       "budget": 3000,
       "travelers": 2
     }
   }
   ```

2. **用户选择要纳入的资源：**
   - `calendar://my-calendar/June-2024`（来自日历服务器）
   - `travel://preferences/europe`（来自旅行服务器）
   - `travel://past-trips/Spain-2023`（来自旅行服务器）

3. **AI 使用工具处理请求：**

   AI 首先读取所有选定的资源以收集上下文——识别日历中可用的日期、从旅行偏好中了解偏好的航空公司和酒店类型，并发现过往行程中曾体验过的地点。

   利用这些上下文，AI 随后执行 AI 应用提供的提示词。在我们的示例中，AI 应用将已连接 MCP 天气服务器的天气工具暴露给模型。因为天气会影响旅行计划，AI 在解读提示词时选择调用 `checkWeather()`。

   结果，AI 执行了一系列工具：

   - `searchFlights()` - 查询纽约到巴塞罗那航班的航空公司
   - `checkWeather()` - 检索旅行日期的气候预报

   AI 随后利用这些信息进行预订和后续步骤，并在必要时请求用户批准：
   - `bookHotel()` - 在指定的预算内寻找酒店
   - `createCalendarEvent()` - 将该次旅行添加到用户的日历
   - `sendEmail()` - 发送带有行程详情的确认邮件

**结果：** 通过多个 MCP 服务器，用户完成了对一次量身定制、契合其日程的巴塞罗那旅行的研究和预订。"规划假期"提示词引导 AI 在不同服务器之间把资源（日历可用情况和旅行历史）与工具（搜索航班、预订酒店、更新日历）结合起来——收集上下文并执行预订。原本可能需要数小时的任务，借助 MCP 在几分钟内就完成了。
