本矩阵展示哪些 MCP 客户端支持各项 [官方扩展](/docs/mcp/extensions/overview)。扩展始终是选择加入的：只有当客户端和服务端都在其 [能力](/docs/mcp/extensions/overview#negotiation) 的 `extensions` 字段中声明支持时，客户端才会使用某项扩展。

<Callout>

此列表由社区维护。如果你发现任何不准确之处，或希望添加、更新信息，请 [提交 pull request](https://github.com/modelcontextprotocol/modelcontextprotocol/pulls)。

</Callout>

| [OAuth 客户端凭证](/docs/mcp/extensions/auth/oauth-client-credentials)                 | `io.modelcontextprotocol/oauth-client-credentials`         | 无需交互式用户登录的机器到机器认证           |
| [企业级托管授权](/docs/mcp/extensions/auth/enterprise-managed-authorization) | `io.modelcontextprotocol/enterprise-managed-authorization` | 通过企业 IdP 实现的集中式访问控制                    |
| [通过 MCP 提供技能](/docs/mcp/extensions/skills/overview)                                        | `io.modelcontextprotocol/skills`                           | 发现技能并读取其指令和支持文件 |

## 为你的客户端添加扩展支持

如果你正在构建 MCP 客户端并希望实现扩展支持：

1. 查看扩展规范（例如 [ext-auth](https://github.com/modelcontextprotocol/ext-auth) 或 [ext-apps](https://github.com/modelcontextprotocol/ext-apps) 仓库中的规范）
2. 在客户端每次请求的 `_meta` 中发送的 `io.modelcontextprotocol/clientCapabilities` 的 `extensions` 字段里声明支持，并从其 [`server/discover`](/docs/mcp/specification/draft/server/discover) 响应中读取服务端的 `extensions`
3. 实现扩展的协议要求
4. 提交 pull request 以更新本矩阵

关于能力协商机制的详情，请参阅 [扩展概览](/docs/mcp/extensions/overview#negotiation)。
