title: 为已发布的 MCP 服务器进行版本管理
---


<Callout>
  MCP Registry 目前处于预览阶段。在正式发布（general availability）之前可能出现破坏性变更或数据重置。如果您遇到任何问题，请在 [GitHub](https://github.com/modelcontextprotocol/registry/issues) 上报告。
</Callout>

MCP 服务器**必须**在 `server.json` 中定义版本字符串。例如：

```json server.json highlight={6}
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json",
  "name": "io.github.username/email-integration-mcp",
  "title": "Email Integration",
  "description": "Send emails and manage email accounts",
  "version": "1.0.0",
  "packages": [
    {
      "registryType": "npm",
      "identifier": "@username/email-integration-mcp",
      "version": "1.0.0",
      "transport": {
        "type": "stdio"
      }
    }
  ]
}
```

版本字符串在服务器的每次发布中**必须**是唯一的。一旦发布，版本字符串（以及其他元数据）就不能更改。

## 版本格式

MCP Registry 推荐使用[语义化版本](https://semver.org/)，但也支持任何版本的字符串格式。当服务器发布时，MCP Registry 会尝试将其版本解析为语义化版本字符串以用于排序，并在适当时将版本标记为 "latest"。如果解析失败，该版本将始终被标记为 "latest"。

<Callout type="warn">

如果服务器使用语义化版本字符串，却发布了一个_不_符合语义化版本的新版本，那么即使该版本在其他情况下会在语义化版本字符串之前排序，也会被标记为 "latest"。

</Callout>

作为错误预防机制，MCP Registry 禁止使用看起来是引用版本范围的版本字符串。

| 示例           | 类型                | 指引                              |
| -------------- | ------------------- | --------------------------------- |
| `1.0.0`        | 语义化版本          | **推荐**                          |
| `2.1.3-alpha`  | 语义化预发布版本    | **推荐**                          |
| `1.0.0-beta.1` | 语义化预发布版本    | **推荐**                          |
| `3.0.0-rc.2`   | 语义化预发布版本    | **推荐**                          |
| `2025.11.25`   | 语义化日期          | 推荐                              |
| `2025.6.18`    | 语义化日期          | 推荐 **（⚠️警告！⚠️）**            |
| `2025.06.18`   | 非语义化日期        | 允许 **（⚠️警告！⚠️）**            |
| `2025-06-18`   | 非语义化日期        | 允许                              |
| `v1.0`         | 带前缀的版本        | 允许                              |
| `^1.2.3`       | 版本范围            | 禁止                              |
| `~1.2.3`       | 版本范围            | 禁止                              |
| `>=1.2.3`      | 版本范围            | 禁止                              |
| `<=1.2.3`      | 版本范围            | 禁止                              |
| `>1.2.3`       | 版本范围            | 禁止                              |
| `<1.2.3`       | 版本范围            | 禁止                              |
| `1.x`          | 版本范围            | 禁止                              |
| `1.2.*`        | 版本范围            | 禁止                              |
| `1 - 2`        | 版本范围            | 禁止                              |
| `1.2 \|\| 1.3` | 版本范围            | 禁止                              |

## 最佳实践

### 使用语义化版本

对版本字符串使用[语义化版本](https://semver.org/)。

### 使服务器版本与软件包版本保持一致

对于本地服务器，使服务器版本与底层软件包版本保持一致，以避免混淆：

```json server.json highlight={2,7}
{
  "version": "1.2.3",
  "packages": [
    {
      "registryType": "npm",
      "identifier": "@my-username/my-server",
      "version": "1.2.3",
      "transport": {
        "type": "stdio"
      }
    }
  ]
}
```

如果有多个底层软件包，则使用服务器版本表示整体发布版本：

```json server.json highlight={2,7,15}
{
  "version": "1.3.0",
  "packages": [
    {
      "registryType": "npm",
      "identifier": "@my-username/my-server",
      "version": "1.3.0",
      "transport": {
        "type": "stdio"
      }
    },
    {
      "registryType": "nuget",
      "identifier": "MyUsername.MyServer",
      "version": "1.0.0",
      "transport": {
        "type": "stdio"
      }
    }
  ]
}
```

### 使服务器版本与远程 API 版本保持一致

对于带有 API 版本的远程服务器，服务器版本应与 API 版本保持一致：

```json server.json highlight={2,6}
{
  "version": "2.1.0",
  "remotes": [
    {
      "type": "streamable-http",
      "url": "https://api.myservice.com/mcp/v2.1"
    }
  ]
}
```

### 对仅限 Registry 的更新使用预发布版本

如果您预期在_不_更改底层软件包或远程 URL 的情况下多次发布服务器——例如，为了更新其他部分的元数据——请使用语义化预发布版本：

```json server.json highlight={2}
{
  "version": "1.2.3-1",
  "packages": [
    {
      "registryType": "npm",
      "identifier": "@my-username/my-server",
      "version": "1.2.3",
      "transport": {
        "type": "stdio"
      }
    }
  ]
}
```

<Callout type="warn">

根据语义化版本规范，`1.2.3-1` 等预发布版本在排序上位于 `1.2.3` 等常规语义化版本之前。因此，如果您在对应的常规版本_之后_发布预发布版本，则该预发布版本**不会**被标记为 "latest"。

</Callout>

## 聚合器建议

MCP Registry 聚合器**应当**：

1. 在可能的情况下尝试将版本解释为语义化版本
2. 使用以下版本比较规则：
   - 如果一个版本被标记为 "latest"，则将其视为更新
   - 如果两个版本都是有效的语义化版本，则使用语义化版本比较规则
   - 如果两个版本都不是有效的语义化版本，则比较发布时间戳
   - 如果一个版本是有效的语义化版本而另一个不是，则将语义化版本视为更新
