**TL;DR**：MCP Registry 相当宽松！我们只删除非法内容、恶意软件、垃圾信息以及完全无法运行的服务器。

## 适用范围

本政策适用于位于 `registry.modelcontextprotocol.io` 的官方 MCP Registry。

子注册中心可能有自己的审核政策。如果您对某个子注册中心上的内容有疑问，请直接联系他们。

## 免责声明

MCP Registry **不**对审核工作做出任何保证，消费者应假定审核非常有限甚至没有审核。

MCP Registry 是一个社区支持的项目，我们积极的审核能力有限。我们在很大程度上依赖上游软件包注册中心（如 NPM、PyPI 和 Docker）或下游子注册中心（如 GitHub MCP Registry）进行更深入的审核。

这意味着 MCP Registry 中可能存在根据本政策应予删除、但尚未被我们删除的内容。消费者应相应地对待抓取的数据。

## 我们会删除的内容

我们将删除包含以下内容的服务器：

- 非法内容，包括淫秽内容、版权侵权和黑客工具
- 恶意软件，无论其意图如何
- 垃圾信息，尤其是干扰注册中心的大规模创建的服务器。示例：
  - 同一服务器以不同名称被多次提交
  - 一个服务器除了在固定响应中添加一些营销文案外什么也不做
  - 一个描述中塞满营销文案但实现与之无关的服务器
- 无法正常运行的服务器

## 我们不会删除的内容

一般来说，我们相信保持注册中心的开放性，并将审核工作推给子注册中心。因此，我们**不会**删除：

- 质量低下或有缺陷的服务器
- 存在安全漏洞的服务器
- 与其他服务器功能相同的服务器
- 提供或包含成人内容的服务器

## 删除是如何进行的

当我们删除一个服务器时，我们会将该服务器的 `status` 设置为 `"deleted"`，但服务器的元数据仍然可以通过 MCP Registry API 访问。聚合器随后可以将该服务器从它们的索引中删除。

在极端情况下，我们可能会覆盖或清除服务器的元数据。例如，当元数据本身不合法时。

## 申诉

认为我们搞错了？在我们的 [GitHub 代码仓库](https://github.com/modelcontextprotocol/registry) 上提交一个 issue，并附上：

- 服务器的名称
- 您认为该服务器不符合以上删除标准的理由

## 本政策的变更

我们仍在学习如何最好地运营 MCP Registry！因此，我们将来可能会修改本政策。
