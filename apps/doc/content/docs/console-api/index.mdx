## 这是什么

控制台是一个持续采集公开仓库数据的服务：它记录每个 stargazer 的到达时间，判定规则跑出的结论（异动）和周期榜单就是它的产品面。这一组文档描述它对外暴露的全部接口，一共 17 个路由，分成五种调用者：

| 调用者     | 接口                              | 鉴权                               | 文档                                            |
| ---------- | --------------------------------- | ---------------------------------- | ----------------------------------------------- |
| 任何持有 key 的调用方 | 仓库档案、区间统计、排行与周期目录 | `Bearer <api-key>`（逐 Key scope） | 控制台站内文档的「API 参考」                    |
| 外部采集器 | 仓库登记与项目发布                 | `Bearer <api-key>`（逐 Key scope） | [写入 API](./projects)                          |
| 调度器     | 定时任务与单任务触发              | `Bearer CRON_SECRET`               | [调度器](./scheduler)                           |
| Web 端     | 技能拉取与订阅邮件                | `Bearer SKILLS_WEBHOOK_TOKEN` / 无 | [技能导出](./skills-sync)、[订阅](./newsletter) |
| 浏览器     | 账号、会话、短信与邮件验证码      | 会话 cookie / 一次性 token         | [认证](./authentication)、[账号](./account)     |
| 控制台前端 | 13 个 tRPC 路由组                 | 会话 + 角色                        | [tRPC](./trpc)                                  |

## Base URL

所有示例的 base URL 都是控制台站点的域名 https://vercelai.cn：

```bash
export CONSOLE_ORIGIN=https://vercelai.cn
curl "$CONSOLE_ORIGIN/api/v1/rankings/weekly" \
  -H "Authorization: Bearer $CONSOLE_API_KEY"
```

用 `curl` 时不需要处理 CORS：这些端点是给机器读的，返回 `Content-Type: application/json`。每个端点都要凭据，没有免鉴权旁路。

## 鉴权的四种形态

控制台没有单一的鉴权机制，而是四条互不相同的路，选哪条取决于调用者是谁：

### 作用域 API Key

`/api/v1/*` 走这一条。`Authorization: Bearer <api-key>`，Key 存在 `api_keys` 表里**按哈希查找**，不是和某个环境变量比大小。它和共享密钥的差别不是"更现代"，而是三件共享密钥做不到的事：

- **可单独吊销**：删掉这一行，这个集成立刻失效，不必轮换全局环境变量。
- **带作用域**：`repos:write` 与 `projects:write` 是两把不同的钥匙。`projects:write` 意味着「把任意仓库推上公开站」，因此它默认不在任何自助签发的范围内，只能由管理员通过 `apiKeys.create` 显式授予。
- **带归属**：Key 自带的 `submitter_id` 被记成这次写入的提交人，调用方不需要在 body 里自称是谁，也不被相信。

限流按 Key 配（`rpm` / `rpd`），保护的是下游：读榜单很便宜，而 `POST /api/v1/repos` 会触发一次 GitHub 抓取，两者的安全上限差一个数量级。

### 共享密钥

`Authorization: Bearer <secret>`，常量时间比较。调度器与技能导出用的是这一条：

| 环境变量                     | 保护什么                                                | 没有配置时   |
| ---------------------------- | ------------------------------------------------------- | ------------ |
| `CRON_SECRET`                | `GET/POST /api/cron/github`、`POST /api/webhook/{task}` | 返回 **404** |
| `SKILLS_WEBHOOK_TOKEN`       | `GET /api/skills-sync/export`                           | 返回 **404** |
| `GITHUB_DATA_WEBHOOK_SECRET` | 出站技能 webhook 的签名                                 | 不推送       |

<Callout>
  没有配置密钥时接口返回 `404` 而不是
  `401`。这是刻意的：一个未配置的实例不应该向任何人确认「这里有一个需要鉴权的写接口」——确认接口存在本身就是一个可以被动收集的信息。**不要**把这个
  404 当成路径写错了而反复重试，它意味着服务端缺配置。
</Callout>

共享密钥没有过期时间、没有作用域、不能单独吊销。吊销靠轮换环境变量并重启实例。这两个端点都是机器对机器的固定内部集成（调度器、技能导出），持有密钥的调用方本来就是可信的内部系统，为它们引入按 Key 的作用域只会让运维更难而不会更安全——需要按调用方区分权限的写接口走上面的作用域 API Key。

### 会话 cookie

`/api/auth/*`、`/api/user/*` 与 `/api/trpc/*` 由 [Better Auth](https://www.better-auth.com) 签发的会话 cookie 鉴权。浏览器里是 `HttpOnly` cookie；脚本调用时用 `credentials: "include"`，跨域还需要把 origin 放进 `BETTER_AUTH_TRUSTED_ORIGINS`。

### 一次性 token

短信相关接口不走会话，也不共享密钥：

- 滑块验证码换取的 token 放在请求头 `X-Temp-Captcha-Token`，**一次性**，消费后立即失效。
- 退订链接里的 token 是对邮箱地址签名的 HMAC，同一个地址重复点击是幂等的。

## 错误格式

错误体的形状取决于鉴权层。`/api/v1/*` 是 `{"error": {"code", "message", "detail"?}}`，其余接口是 `{"error": "<machine_code>"}`。两种形状里那个稳定的机器码（`error.code` / `error` 本身）是**唯一**用来分支的东西，`message` 和 `detail` 是给人看的，可能随时改。**请按机器码分支，不要匹配文本。**

## 版本与兼容性

没有版本前缀。所有机器对机器的读取都走 `/api/v1/*`，`/api/v1` 之外没有免鉴权的
JSON 端点。

这些接口的稳定性承诺只有一条：**字段只增不改不删**。新增字段不构成破坏性变更，因此
调用方应当忽略不认识的字段。调度器与技能导出的响应形状**没有**这样的承诺——它们
服务于特定的集成方，改形状时调用方一起改。

## 相关的机器可读入口

控制台自己提供两个给 agent 读的文本入口，与站内这四个端点的字段表同源：

- <code>https://vercelai.cn/llms.txt</code> ——
  全站页面索引，每个页面一句可引用的描述
- <code>https://vercelai.cn/llms-full.txt</code> —— 判定规则全文、FAQ 原文、开放
  API 的端点清单与榜单字段表

其中判定规则的每个数字都读自控制台自己的 `THRESHOLDS`，因此与线上行为不会脱节：改了下界，两处一起改。
