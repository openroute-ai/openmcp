Alice 护栏会根据你在 Alice 中配置的策略对提示词和模型响应进行筛查。每次调用时，它都会将请求转发给 Alice，由 Alice 决定负载中哪些内容值得评估，并返回一个护栏会执行的裁决：允许该调用、拦截该调用、替换被标记的文本，或记录一条检测结果并放行该调用。

策略是按应用而非全局配置的，因此同一个代理可以在共享同一项目凭据的情况下，为每个团队或产品强制执行不同的策略集。某个调用属于哪个应用是在 OpenMCP 虚拟密钥上命名的，详见[为应用命名](#naming-the-application)。

## 快速开始

### 1. 获取你的 Alice API 密钥

在 Alice 平台中，打开**账户设置**，然后进入**API 密钥**，为你想执行其策略的项目创建一个密钥。

### 2. 将 Alice 添加到你的 OpenMCP config.yaml

在 `guardrails` 部分定义护栏。一个条目即可覆盖两个方向；在 `mode` 中同时列出两个钩子点，以便对提示词和响应都进行筛查。

```yaml title="config.yaml"
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: alice
    openmcp_params:
      guardrail: alice
      mode: [pre_call, post_call]
      default_on: true
      api_key: os.environ/ALICE_API_KEY
```

### 3. 启动 OpenMCP 代理

```shell
export OPENAI_API_KEY=sk-...
export ALICE_API_KEY=...
openmcp --config config.yaml
```

### 4. 创建一个指定应用名称的虚拟密钥

Alice 会从已认证的虚拟密钥中解析应用，因此使用主密钥发出的请求会被拒绝。请创建一个指定了应用名称的密钥：

```shell
curl -sSLX POST 'http://0.0.0.0:4000/key/generate' \
--header 'Authorization: Bearer sk-1234' \
--header 'Content-Type: application/json' \
--data '{
  "key_alias": "payments-bot",
  "metadata": {"alice_app_id": "payments-bot"}
}'
```

### 5. 发出你的第一个请求

## 为应用命名

一个 Alice 凭据覆盖整个项目，而一个项目通常包含多个应用，因此每个请求上必须有某些信息来表明应适用哪个应用的策略。这个信息就是虚拟密钥，而且只能是虚拟密钥，因为它是请求上唯一由代理本身认证过的内容。

为每个应用签发一个密钥并在密钥上命名该应用，如上面的第 4 步所示。优先读取密钥元数据中的 `alice_app_id`；密钥的 `key_alias` 作为回退，因此按应用命名密钥且不设置元数据也可以。这两个值都必须与 Alice 中该应用的 Application ID 匹配，即添加应用表单上显示的自由格式标识符。

调用方无法覆盖这一点。代理会在任何护栏看到请求之前，从请求中剥离调用方提供的 `user_api_key_*` 字段，因此开发者无法将自己的流量指向一个策略比其密钥对应应用更宽松的应用。当密钥未指定任何应用时，请求会被直接拒绝，而不是基于猜测进行评估。

## 发送给 Alice 的内容

护栏会原样转发钩子自身的参数，不做任何重命名或筛选，因此"什么内容值得评估"始终是 Alice 的决定，而不是网关固定预设的。

凭据是唯一的例外。无论 `secret_fields`、`api_key`、`raw_headers`、`headers` 和 `provider_specific_header` 出现在负载中的任何嵌套层级，都会被移除，因为调用方的 `Authorization` 令牌就存在于其中几项里，而护栏端点不是发送它的地方。OpenMCP 已经将这些字段排除在自己的 spend 日志之外。移除操作在副本上进行；管线的其余部分仍然能看到原始数据。

## 裁决

Alice 会从四种裁决中返回一种。`ALLOW` 会继续执行。`BLOCK` 会抛出一个携带策略自身消息的 400。`MASK` 会在提交文本的位置上替换为脱敏后的文本；如果某个替换无法应用，则会改为拦截该调用，因此部分经过掩码的内容永远无法到达模型。`DETECT` 会继续执行并记录一条携带关联 ID 的警告，Alice 端记录的检测结果正是通过它关联回特定请求的。

任何其他响应，包括无法读取的响应，都会被当作故障（outage）处理，而不是当作放行。

## 支持的参数

`api_key` 是必填项，既可以配置在 config 中，也可以通过 `ALICE_API_KEY` 环境变量提供。

| 参数 | 默认值 | 描述 |
|---|---|---|
| `api_key` | `ALICE_API_KEY` | Alice 项目 API 密钥 |
| `api_base` | `https://api.alice.io` | 仅主机地址；回退到 `ALICE_API_BASE`。评估路径会自动追加 |
| `unreachable_fallback` | `fail_closed` | 当 Alice 无法访问、返回 5xx 或返回无法读取的内容时的行为。`fail_open` 会放行调用并改为记录一条 critical 日志 |

来自 Alice 的 4xx 响应（例如凭据被拒绝）不会被当作不可达处理。这是配置错误而非故障，因此它会向上抛出，而不是静默地 fail open。

## 支持的模式

Alice 支持 `pre_call`、`during_call` 和 `post_call`。使用 `pre_call` 在模型被调用前筛查提示词，使用 `post_call` 筛查补全结果。

流式响应在 `post_call` 阶段进行筛查，此时拦截有效但掩码无效：OpenMCP 默认的流式转换会丢弃返回的文本重写，因此对流式响应给出的 `MASK` 裁决不生效，而 `BLOCK` 仍会停止该流。如果你需要掩码可靠生效，请在 `pre_call` 阶段筛查提示词。
