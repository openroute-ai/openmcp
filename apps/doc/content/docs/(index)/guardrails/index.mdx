在 OpenMCP 代理（AI 网关）上设置提示词注入检测、PII 掩码

## 1. 在 OpenMCP config.yaml 中定义护栏

在 `guardrails` 配置段下设置你的护栏

```yaml
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: general-guard
    openmcp_params:
      guardrail: cato_networks
      mode: [pre_call, post_call]
      api_key: os.environ/CATO_API_KEY
      api_base: os.environ/CATO_API_BASE
      default_on: true # Optional
  
  - guardrail_name: "aporia-pre-guard"
    openmcp_params:
      guardrail: aporia  # supported values: "aporia", "lakera"
      mode: "during_call"
      api_key: os.environ/APORIA_API_KEY_1
      api_base: os.environ/APORIA_API_BASE_1
  - guardrail_name: "aporia-post-guard"
    openmcp_params:
      guardrail: aporia  # supported values: "aporia", "lakera"
      mode: "post_call"
      api_key: os.environ/APORIA_API_KEY_2
      api_base: os.environ/APORIA_API_BASE_2
    guardrail_info: # Optional field, info is returned on GET /guardrails/list
      # you can enter any fields under info for consumers of your guardrail
      params:
        - name: "toxicity_score"
          type: "float"
          description: "Score between 0-1 indicating content toxicity level"
        - name: "pii_detection"
          type: "boolean"

# Example Presidio guardrail config with entity actions + confidence score thresholds
  - guardrail_name: "presidio-pii"
    openmcp_params:
      guardrail: presidio
      mode: "pre_call"
      presidio_language: "en"
      pii_entities_config:
        CREDIT_CARD: "MASK"
        EMAIL_ADDRESS: "MASK"
        US_SSN: "MASK"
      presidio_score_thresholds:  # minimum confidence scores for keeping detections
        CREDIT_CARD: 0.8
        EMAIL_ADDRESS: 0.6

# Example Pillar Security config via Generic Guardrail API
  - guardrail_name: "pillar-security"
    openmcp_params:
      guardrail: generic_guardrail_api
      mode: [pre_call, post_call]
      api_base: https://api.pillar.security/api/v1/integrations/openmcp
      api_key: os.environ/PILLAR_API_KEY
      additional_provider_specific_params:
        plr_mask: true
        plr_evidence: true
        plr_scanners: true
```

对于通用护栏 API，你还可以设置**静态请求头**（`headers`：每次请求发送的键/值对）和**动态请求头**（`extra_headers`：要转发的请求头名称列表）。参见 [Generic Guardrail API - 静态与动态请求头](/docs/adding_provider/generic_guardrail_api#static-and-dynamic-headers)。

### `mode`（事件钩子）支持的值

- `pre_call` 在 LLM 调用**之前**对**输入**运行
- `post_call` 在 LLM 调用**之后**对**输入与输出**运行
- `during_call` 在 LLM 调用**期间**对**输入**运行。与 `pre_call` 相同，但与 LLM 调用并行执行。只有护栏检查完成后才会返回响应
- 上述值的列表，用于运行多种模式，例如 `mode: [pre_call, post_call]`

### 在护栏评估中跳过系统消息

你可以让护栏停止扫描 `role: system` 的内容，同时仍将完整的 `messages` 列表发送给模型。

**全局**，在 `openmcp_settings` 中：

```yaml
openmcp_settings:
  skip_system_message_in_guardrail: true
```

**按护栏**，在该护栏的 `openmcp_params` 下：设置 `skip_system_message_in_guardrail: true` 或 `false`。如果省略，则使用全局 `openmcp_settings` 的值；护栏级 `false` 会强制包含系统消息，即使全局标志为 `true`。

**通过 OpenMCP UI**，在 OpenMCP Admin Dashboard 中**创建**或**编辑**护栏时，设置 **Skip system messages in guardrail**（创建时位于 Basic Info 下，或位于编辑/护栏设置流程中）：

| UI 选项                             | 效果                                                                                 |
| ------------------------------------- | -------------------------------------------------------------------------------------- |
| **Use global default**                | 使用你的代理配置中的 `openmcp_settings.skip_system_message_in_guardrail`        |
| **Yes — exclude from guardrail scan** | 设置护栏级 `skip_system_message_in_guardrail: true`                            |
| **No — always include in scan**       | 设置护栏级 `skip_system_message_in_guardrail: false`（覆盖全局跳过） |

<img src="/images/docs/guardrails/skip_system_message_guardrail_ui.png" alt="Create guardrail: Skip system messages in guardrail dropdown with Use global default, Yes exclude from guardrail scan, and No always include in scan" style={{ width: '100%', maxWidth: '900px', height: 'auto' }} />

### 在护栏评估中跳过工具消息

同理，适用于 `role: tool` 的内容：让护栏停止扫描工具调用结果，同时仍将完整的 `messages` 列表发送给模型。

**全局**（在 `openmcp_settings` 中）：

```yaml
openmcp_settings:
  skip_tool_message_in_guardrail: true
```

**按护栏**：在该护栏的 `openmcp_params` 下，设置 `skip_tool_message_in_guardrail: true` 或 `false`，其全局/护栏级优先级与上面的系统消息标志相同。

**通过 OpenMCP UI**：以相同方式设置 **Skip tool messages in guardrail**，位于上述系统消息下拉框正下方，同样带有三个选项（**Use global default**、**Yes, exclude from guardrail scan**、**No, always include in scan**）。

### 这些跳过标志适用的位置

**适用于：** **OpenAI Chat Completions**（`/v1/chat/completions`）和 **Anthropic Messages**（`/v1/messages`）上的**统一**护栏路径（实现了 `apply_guardrail` 并通过 OpenMCP 的消息转换层运行的提供方）。例如 Presidio、Bedrock 护栏、`openmcp_content_filter`、OpenAI Moderation、Generic Guardrail API 以及定义了 `apply_guardrail` 的自定义代码护栏。**Lakera v2** 也遵守这两个标志，尽管它通过直接钩子而非统一路径运行；参见 [Lakera AI](./lakera_ai#supported-params)。

**不适用于：** 其他仅通过直接钩子在原始请求上运行的护栏（例如 Aporia、DynamoAI、Javelin、Lasso、Pangea、Model Armor、Azure Content Safety 钩子、Guardrails AI、AIM、Cato Networks、工具权限、MCP 安全）。在这些端点使用相同的转换层之前（例如 Responses API、嵌入、语音），这些标志也不适用。

## **默认开启的护栏**

在护栏配置中设置 `default_on: true`，即可在每个请求上运行该护栏。如果你想在每个请求上都运行护栏，而无需用户自己指定，这会非常有用。

**注意：**即使指定了其他护栏或为空护栏数组，这些护栏仍会运行。

```yaml
guardrails:
  - guardrail_name: "aporia-pre-guard"
    openmcp_params:
      guardrail: aporia
      mode: "pre_call"
      default_on: true
```

**测试请求**

在此请求中，由于设置了 `default_on: true`，护栏 `aporia-pre-guard` 会在每个请求上运行。

```shell
curl -i http://localhost:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-npnwjPQciVRok5yNZgKmFQ" \
  -d '{
    "model": "{{openai_small}}",
    "messages": [
      {"role": "user", "content": "hi my email is ishaan@berri.ai"}
    ]
  }'
```

**预期响应**

你的响应头将包含 `x-openmcp-applied-guardrails`，其中列出已应用的护栏

```
x-openmcp-applied-guardrails: aporia-pre-guard
```

      "guardrails": {

          "extra_body": {
            "success_threshold": 0.9
          }

    }

)

print(response)

### ✨ 基于标签的护栏模式

<EnterpriseFeature />

根据 user-agent 请求头运行护栏。这在 OpenWebUI 上运行调用前检查、而仅在 Claude CLI 的日志中进行掩码时很有用。

`default` 和标签值都可以是单个模式字符串或模式列表。

```yaml
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: {{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "guardrails_ai-guard"
    openmcp_params:
      guardrail: guardrails_ai
      guard_name: "pii_detect" # 👈 Guardrail AI guard name
      mode:
        tags:
            "User-Agent: claude-cli": "logging_only"                 # Claude CLI - only mask in logs
        default: "pre_call"               # Default mode when no tags match
      api_base: os.environ/GUARDRAILS_AI_API_BASE # 👈 Guardrails AI API Base. Defaults to "http://0.0.0.0:8000"
      default_on: true # run on every request
```

## 规范说明

### YAML 中的 `guardrails` 配置

```yaml
guardrails:
  - guardrail_name: string     # Required: Name of the guardrail
    openmcp_params:            # Required: Configuration parameters
      guardrail: string        # Required: One of "aporia", "bedrock", "guardrails_ai", "lakera", "presidio", "hide-secrets"
      mode: Union[string, List[string], Mode]             # Required: One or more of "pre_call", "post_call", "during_call", "logging_only"
      api_key: string          # Required: API key for the guardrail service
      api_base: string         # Optional: Base URL for the guardrail service
      default_on: boolean      # Optional: Default False. When set to True, will run on every request, does not need client to specify guardrail in request
    guardrail_info:            # Optional[Dict]: Additional information about the guardrail
      
```

模式规范

`default` 和标签值都接受单个字符串或字符串列表。

```python
from openmcp.types.guardrails import Mode

# Single default mode
mode = Mode(
    tags={"User-Agent: claude-cli": "logging_only"},
    default="logging_only"
)

# Multiple default modes
mode = Mode(
    tags={"User-Agent: claude-cli": "logging_only"},
    default=["pre_call", "post_call"]
)

# Multiple modes on a tag value
mode = Mode(
    tags={"User-Agent: claude-cli": ["pre_call", "post_call"]},
    default="logging_only"
)
```

### `guardrails` 请求参数

`guardrails` 参数可以传递给任何 OpenMCP 代理端点（`/chat/completions`、`/completions`、`/embeddings`）。

#### 格式选项

1. 简单列表格式：

```python
{"guardrails": [
    "aporia-pre-guard",
    "aporia-post-guard"
]}
```

1. 高级字典格式：

在此格式中，字典的键是你要运行的 `guardrail_name`

```python
{"guardrails": {
    "aporia-pre-guard": {
        "extra_body": {
            "success_threshold": 0.9,
            "other_param": "value"
        }
    }
}}
```

#### 类型定义

```python
guardrails: Union[
    List[str],                              # Simple list of guardrail names
    Dict[str, DynamicGuardrailParams]       # Advanced configuration
]

class DynamicGuardrailParams:
    extra_body: Dict[str, Any]              # Additional parameters for the guardrail
```
