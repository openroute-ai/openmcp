使用 [Vigil Guard](https://www.vigilguard.ai) 作为 OpenMCP 代理护栏，在聊天输入和模型输出返回给应用程序之前对其进行评估。

**支持的端点：** Vigil Guard 集成支持 chat completions 端点（`/v1/chat/completions`）。

对于 Chat Completions，Vigil Guard 扫描请求和响应文本。在 post-call 检查中，OpenMCP 还会扫描模型生成的 `tool_calls[].function.arguments`；如果 Vigil Guard 返回 `SANITIZED`，OpenMCP 会在返回响应之前用脱敏后的值替换工具调用参数。

在 `tools` 中传递的静态工具 schema 和工具描述不会被此集成扫描。

Vigil Guard Enterprise 是一个 AI 检测与响应平台，用于在运行时保护 LLM 应用程序。它为安全和平台团队提供针对提示词、响应和自主智能体交互的策略层，支持提示词注入防御、敏感数据保护、内容审核、语义漂移检测和 SIEM 导出。

在本地部署 Vigil Guard Enterprise，然后让 OpenMCP 指向已部署的 API。公开安装指南提供了针对 Linux x86_64 主机的基于 Docker 的部署流程。有关当前要求和安装步骤，请参阅 [Vigil Guard 安装指南](https://www.vigilguard.ai/install/)。

## 概述

| 属性 | 详情 |
|----------|---------|
| 提供商 | [Vigil Guard](https://www.vigilguard.ai) |
| OpenMCP 护栏值 | `vigil_guard` |
| 支持的模式 | `pre_call`、`post_call` |
| 支持的行为 | 根据你的 Vigil Guard 策略允许、脱敏或拦截内容 |
| 默认故障行为 | `fail_closed` |
| 所需凭据 | Vigil Guard API 密钥和 API 基础 URL |
| 部署 | 本地 Vigil Guard Enterprise 实例 |

## 快速开始

### 1. 部署或访问 Vigil Guard Enterprise

使用现有的 Vigil Guard Enterprise 部署，或按照 [Vigil Guard 安装指南](https://www.vigilguard.ai/install/) 安装一个。

公开安装流程从以下命令开始：

```shell
curl -fsSL https://get.vigilguard.ai -o /tmp/install.sh && sudo bash /tmp/install.sh
```

安装指南列出了当前的最低要求，包括 Linux x86_64、带 Compose v2 的 Docker Engine、`30 GB` RAM、`70 GB` 可用磁盘、可用端口 `80` 和 `443`、到 Docker Hub 的互联网访问，以及用于镜像签名验证的 `cosign`。

安装后，使用已部署的 API 主机名作为 `VIGIL_GUARD_URL`。例如，如果你的部署主机名是 `vge.company.com`，API URL 通常是：

```shell
export VIGIL_GUARD_URL="https://api.vge.company.com"
```

### 2. 获取 Vigil Guard 凭据

你需要：

- `VIGIL_GUARD_API_KEY`: 你的 Vigil Guard API 密钥
- `VIGIL_GUARD_URL`: 你的 Vigil Guard API 基础 URL

有关 Vigil Guard 产品信息，请访问 [https://www.vigilguard.ai](https://www.vigilguard.ai)。如需支持，请联系 `contact@vigilguard.ai`。

### 3. 在 `config.yaml` 中定义护栏

在 `guardrails` 部分下定义你的护栏。

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "vigil-guard-input"
    openmcp_params:
      guardrail: vigil_guard
      mode: "pre_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL
```

#### `mode` 支持的值

- `pre_call` 在 LLM 调用**之前**运行，作用于**用户输入**。
- `post_call` 在 LLM 调用**之后**运行，作用于**模型输出**。

### 4. 设置环境变量

```shell
export VIGIL_GUARD_API_KEY="your-vigil-guard-api-key"
export VIGIL_GUARD_URL="https://api.your-hostname"
export OPENAI_API_KEY="your-openai-api-key"
```

### 5. 启动 OpenMCP 网关

```shell
openmcp --config config.yaml --detailed_debug
```

## 高级配置

### 输入和输出护栏

当你想要扫描用户输入和模型输出时，使用单独的护栏条目。

```yaml showLineNumbers title="config.yaml"
guardrails:
  - guardrail_name: "vigil-guard-input"
    openmcp_params:
      guardrail: vigil_guard
      mode: "pre_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL

  - guardrail_name: "vigil-guard-output"
    openmcp_params:
      guardrail: vigil_guard
      mode: "post_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL
```

然后将两个护栏附加到一个请求：

```shell showLineNumbers title="Curl Request"
curl -i http://0.0.0.0:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-1234" \
  -d '{
    "model": "{{openai_small}}",
    "messages": [
      {"role": "user", "content": "Write a short API security checklist."}
    ],
    "guardrails": ["vigil-guard-input", "vigil-guard-output"]
  }'
```

### 默认运行

设置 `default_on: true` 可在不需要客户端在每个请求中传递护栏名称的情况下运行护栏。

```yaml showLineNumbers title="config.yaml"
guardrails:
  - guardrail_name: "vigil-guard-input"
    openmcp_params:
      guardrail: vigil_guard
      mode: "pre_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL
      default_on: true
```

### 故障开放模式

默认情况下，Vigil Guard 故障关闭。如果无法到达护栏后端，OpenMCP 会返回错误，而不是将未扫描的内容发送到模型。

设置 `unreachable_fallback: fail_open` 可在护栏后端不可达时允许请求继续。

```yaml showLineNumbers title="config.yaml"
guardrails:
  - guardrail_name: "vigil-guard-input"
    openmcp_params:
      guardrail: vigil_guard
      mode: "pre_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL
      unreachable_fallback: fail_open
```

<Callout type="warn">

`unreachable_fallback: fail_open` 仅在无法到达 Vigil Guard 后端或返回无效护栏响应时适用。它不会覆盖策略拦截决定。

</Callout>

## 支持的参数

```yaml showLineNumbers title="config.yaml"
guardrails:
  - guardrail_name: "vigil-guard-input"
    openmcp_params:
      guardrail: vigil_guard
      mode: "pre_call"
      api_key: os.environ/VIGIL_GUARD_API_KEY
      api_base: os.environ/VIGIL_GUARD_URL
      default_on: false
      unreachable_fallback: fail_closed
```

| 参数 | 环境变量 | 默认值 | 描述 |
|-----------|--------------|---------|-------------|
| `guardrail` | - | 必需 | 必须设置为 `vigil_guard`。 |
| `mode` | - | 必需 | 支持的值：`pre_call`、`post_call`。 |
| `api_key` | `VIGIL_GUARD_API_KEY` | 必需 | Vigil Guard API 密钥。 |
| `api_base` | `VIGIL_GUARD_URL` | 必需 | Vigil Guard API 基础 URL。 |
| `default_on` | - | `false` | 当为 `true` 时，OpenMCP 会在每个请求上运行此护栏，而无需客户端传递护栏名称。 |
| `unreachable_fallback` | - | `fail_closed` | 使用 `fail_closed` 在后端故障时拦截，或使用 `fail_open` 在后端不可达时允许请求继续。 |

## 错误处理

| 场景 | 行为 |
|----------|----------|
| Vigil Guard 允许内容 | OpenMCP 正常继续请求。 |
| Vigil Guard 脱敏内容 | OpenMCP 转发脱敏后的内容。 |
| Vigil Guard 拦截内容 | OpenMCP 返回带有 HTTP `400` 的护栏错误。 |
| 后端故障且 `unreachable_fallback: fail_closed` | OpenMCP 使请求失败，而不是发送未扫描的内容。 |
| 后端故障且 `unreachable_fallback: fail_open` | OpenMCP 记录后端故障并允许请求继续。 |
