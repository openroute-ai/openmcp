使用 [Prompt Security](https://prompt.security/) 通过输入和输出验证保护您的 LLM 应用免受提示词注入攻击、越狱尝试、有害内容、个人身份信息(PII)泄露以及恶意文件上传的侵害。

## 快速开始

### 1. 在您的 OpenMCP config.yaml 上定义护栏 

在 `guardrails` 部分下定义您的护栏：

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: {{openai_large}}
    openmcp_params:
      model: openai/{{openai_large}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "prompt-security-guard"
    openmcp_params:
      guardrail: prompt_security
      mode: "during_call"
      api_key: os.environ/PROMPT_SECURITY_API_KEY
      api_base: os.environ/PROMPT_SECURITY_API_BASE
      user: os.environ/PROMPT_SECURITY_USER              # Optional: User identifier
      system_prompt: os.environ/PROMPT_SECURITY_SYSTEM_PROMPT  # Optional: System context
      file_sanitization_fail_open: true  # Optional: Allow the original file on timeout (default: true)
      block_on_file_modify: true         # Optional: Block file modify verdicts (default: true)
      default_on: true
```

#### `mode` 支持的值

- `pre_call` - 在 LLM 调用**之前**运行，以验证**用户输入**。阻止检测到策略违规的请求（越狱尝试、有害提示词、个人身份信息(PII)、恶意文件等）
- `post_call` - 在 LLM 调用**之后**运行，以验证**模型输出**。阻止包含有害内容、策略违规或敏感信息的响应
- `during_call` - 同时运行调用前和调用后验证

### 2. 设置环境变量

```shell
export PROMPT_SECURITY_API_KEY="your-api-key"
export PROMPT_SECURITY_API_BASE="https://REGION.prompt.security"
export PROMPT_SECURITY_USER="optional-user-id"  # Optional: for user tracking
export PROMPT_SECURITY_SYSTEM_PROMPT="optional-system-prompt"  # Optional: for context
```

### 3. 启动 OpenMCP 网关 

```shell
openmcp --config config.yaml --detailed_debug
```

## 文件净化

Prompt Security 提供高级文件净化能力，用于检测并阻止上传文件（包括图片、PDF 和文档）中的恶意内容。

### 支持的文件类型

- **图片**：PNG、JPEG、GIF、WebP
- **文档**：PDF、DOCX、XLSX、PPTX
- **文本文件**：TXT、CSV、JSON

### 文件净化的工作原理

当消息包含文件内容（在 data URL 中以 base64 编码）时，护栏会：

1. **提取**消息中的文件数据
2. **上传**文件到 Prompt Security 的净化 API
3. **轮询** API 获取净化结果（带可配置的超时时间）
4. 根据判定结果**采取措施**

判定行为：

- `block`：拒绝请求并附带违规详情
- `modify`：默认拒绝请求。设置 `block_on_file_modify: false` 可用返回的净化内容替换文件内容
- `allow`：文件原样通过

**注意**：文件净化使用基于任务的异步 API。护栏会：
- 提交文件并收到一个 `jobId`
- 轮询 `/api/sanitizeFile?jobId={jobId}`，直到状态为 `done`
- 默认将整个上传并轮询操作限制在 30 秒内
- 默认在超时时放行原始文件

<Callout type="warn">

默认的 `file_sanitization_fail_open: true` 优先保证可用性：当净化超时时，转发原始的未净化文件。设置 `file_sanitization_fail_open: false` 则改为以 HTTP 408 拒绝超时的文件。

</Callout>

## 提示词修改

当检测到违规但可以被消除时，Prompt Security 可以修改内容而不是完全阻止。

本节适用于提示词和响应文本。文件 `modify` 判定默认会被阻止，因为返回的内容可能是提取出来的文本，而不是重建的文件。仅在返回的内容可以安全地作为替换文件内容使用时，才设置 `block_on_file_modify: false`。

### 修改示例

<Tabs items={["输入修改","输出修改"]}>
<Tab>

**原始请求：**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "Tell me about John Doe (SSN: 123-45-6789, email: john@example.com)"
    }
  ]
}
```

**修改后的请求（发送给 LLM）：**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "Tell me about John Doe (SSN: [REDACTED], email: [REDACTED])"
    }
  ]
}
```

请求继续，敏感信息被掩码。

</Tab>

<Tab>

**原始 LLM 响应：**
```
"Here's a sample API key: sk-1234567890abcdef. You can use this for testing."
```

**修改后的响应（返回给用户）：**
```
"Here's a sample API key: [REDACTED]. You can use this for testing."
```

响应中的敏感数据会被自动脱敏。

</Tab>

## 流式支持

Prompt Security 护栏完全支持基于分块验证的流式响应：

```shell
curl -i http://0.0.0.0:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "{{openai_large}}",
    "messages": [
      {"role": "user", "content": "Write a story about cybersecurity"}
    ],
    "stream": true,
    "guardrails": ["prompt-security-guard"]
  }'
```

### 流式行为

- **基于窗口的验证**：分块会被缓冲并按窗口进行验证（默认：250 个字符）
- **智能分块**：在单词边界处分割，避免在单词中间断开
- **实时阻止**：如果检测到有害内容，流式传输会立即停止
- **修改支持**：修改后的分块会实时传输

如果在流式传输过程中检测到违规：

```
data: {"error": "Blocked by Prompt Security, Violations: harmful_content"}
```

## 高级配置

### 文件净化策略

使用这些设置来选择可用性和文件替换行为：

```yaml
guardrails:
  - guardrail_name: "prompt-security-guard"
    openmcp_params:
      guardrail: prompt_security
      mode: "during_call"
      api_key: os.environ/PROMPT_SECURITY_API_KEY
      api_base: os.environ/PROMPT_SECURITY_API_BASE
      file_sanitization_fail_open: true
      block_on_file_modify: true
```

| 设置 | 默认值 | 为 `true` 时的行为 | 为 `false` 时的行为 |
| --- | --- | --- | --- |
| `file_sanitization_fail_open` | `true` | 超时记录错误并转发原始文件 | 超时以 HTTP 408 拒绝请求 |
| `block_on_file_modify` | `true` | 文件 `modify` 判定以 HTTP 400 拒绝请求 | 文件 `modify` 判定替换文件内容 |

### 用户与系统提示词追踪

追踪用户并提供系统上下文以获得更好的安全分析：

```yaml
guardrails:
  - guardrail_name: "prompt-security-tracked"
    openmcp_params:
      guardrail: prompt_security
      mode: "during_call"
      api_key: os.environ/PROMPT_SECURITY_API_KEY
      api_base: os.environ/PROMPT_SECURITY_API_BASE
      user: os.environ/PROMPT_SECURITY_USER              # Optional: User identifier
      system_prompt: os.environ/PROMPT_SECURITY_SYSTEM_PROMPT  # Optional: System context
```

### 通过代码配置

您也可以通过编程方式配置护栏：

```python
from openmcp.proxy.guardrails.guardrail_hooks.prompt_security import PromptSecurityGuardrail

guardrail = PromptSecurityGuardrail(
    api_key="your-api-key",
    api_base="https://eu.prompt.security",
    user="user-123",
    system_prompt="You are a helpful assistant that must not reveal sensitive data.",
    file_sanitization_timeout=30.0,
    file_sanitization_fail_open=True,
    block_on_file_modify=True,
)
```

`file_sanitization_timeout` 为编程方式设置配置整个上传并轮询的截止时间。

### 多护栏配置

配置独立的调用前和调用后护栏，以实现细粒度的控制：

```yaml
guardrails:
  - guardrail_name: "prompt-security-input"
    openmcp_params:
      guardrail: prompt_security
      mode: "pre_call"
      api_key: os.environ/PROMPT_SECURITY_API_KEY
      api_base: os.environ/PROMPT_SECURITY_API_BASE
      
  - guardrail_name: "prompt-security-output"
    openmcp_params:
      guardrail: prompt_security
      mode: "post_call"
      api_key: os.environ/PROMPT_SECURITY_API_KEY
      api_base: os.environ/PROMPT_SECURITY_API_BASE
```

## 安全功能

Prompt Security 可防范以下威胁：

### 输入威胁
- **提示词注入**：检测覆盖系统指令的尝试
- **越狱尝试**：识别绕过技术和指令操纵
- **提示词中的个人身份信息(PII)**：检测用户输入中的个人身份信息
- **恶意文件**：扫描上传文件中内嵌的威胁（恶意软件、脚本、隐写术）
- **文档漏洞利用**：分析 PDF 和 Office 文档中的安全漏洞

### 输出威胁  
- **数据泄露**：防止响应中暴露敏感信息
- **响应中的个人身份信息(PII)**：检测并可脱敏模型输出中的个人身份信息
- **有害内容**：识别暴力、仇恨或非法内容的生成
- **代码注入**：检测响应中可能恶意的代码
- **凭据泄露**：防止 API 密钥、密码和令牌被泄露

### 处置动作

护栏会根据风险采取三种类型的处置动作：

- **`block`**：完全阻止请求/响应，并返回带有违规详情的错误
- **`modify`**：净化提示词或响应文本并允许其继续。默认阻止文件修改
- **`allow`**：内容原样通过

## 违规报告

所有被阻止的请求都包含详细的违规信息：

```json
{
  "error": {
    "message": "Blocked by Prompt Security, Violations: prompt_injection, pii_leakage, embedded_malware",
    "type": "None",
    "param": "None",
    "code": "400"
  }
}
```

违规是逗号分隔的字符串，可帮助您理解内容被阻止的原因。

## 错误处理

### 常见错误

**缺少 API 凭据：**
```
PromptSecurityGuardrailMissingSecrets: Couldn't get Prompt Security api base or key
```
解决方案：设置 `PROMPT_SECURITY_API_KEY` 和 `PROMPT_SECURITY_API_BASE` 环境变量

**文件净化超时：**

默认情况下，护栏会记录超时并转发原始文件。若要改为失败关闭，请配置：

```yaml
file_sanitization_fail_open: false
```

调用方随后会收到：

```
{
  "error": {
    "message": "File sanitization timeout",
    "code": "408"
  }
}
```

对于编程方式设置，请调整 `file_sanitization_timeout` 来更改截止时间。

**无效的文件格式：**
```
{
  "error": {
    "message": "File sanitization failed: Invalid base64 encoding",
    "code": "500"
  }
}
```
解决方案：确保文件在 data URL 中被正确地进行 base64 编码

## 最佳实践

1. **使用 `during_call` 模式**来同时覆盖输入和输出
2. **为生产环境工作负载启用**，使用 `default_on: true` 默认保护所有请求
3. **配置用户追踪**，识别跨用户会话的模式
4. **监控违规**活动，在 Prompt Security 仪表盘中调整策略
5. **全面测试文件上传**，在上线前使用各种文件类型进行测试
6. **选择超时策略**，根据可用性或失败关闭执行哪个更重要来决定
7. **与其他护栏组合使用**，实现纵深防御安全

## 故障排查

### 护栏未运行

检查您的配置中是否启用了该护栏：

```yaml
guardrails:
  - guardrail_name: "prompt-security-guard"
    openmcp_params:
      guardrail: prompt_security
      default_on: true  # Ensure this is set
```

### 文件未被净化

请确认：
1. 文件以正确的 data URL 格式进行 base64 编码
2. 包含 MIME 类型：`data:image/png;base64,...`
3. 内容类型是 `image_url`、`document` 或 `file`

### 高延迟

文件净化会因上传和轮询增加延迟。为优化：
1. 在发送请求前减小文件大小
2. 以编程方式配置护栏时设置 `file_sanitization_timeout`
3. 根据所需的可用性和安全态势选择 `file_sanitization_fail_open`
