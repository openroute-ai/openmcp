## 概览

| 属性 | 详情 |
|-------|-------|
| 描述 | 使用此护栏脱敏个人身份信息(PII)、受保护健康信息(PHI)和其他敏感数据。 |
| 提供者 | [Microsoft Presidio](https://github.com/microsoft/presidio/) |
| 支持的实体类型 | 所有 Presidio 实体类型 |
| 支持的操作 | `MASK`、`BLOCK` |
| 支持的模式 | `pre_call`、`during_call`、`post_call`、`logging_only`、`pre_mcp_call` |
| 语言支持 | 通过 `presidio_language` 参数配置（支持多种语言，包括英语、西班牙语、德语等） |

## 部署选项

## 实体类型、检测置信度分数阈值和作用域配置

- **实体类型**
  - 你可以配置特定的实体类型进行个人身份信息(PII)检测，并决定如何处理每种实体类型（脱敏或阻止）。
- **检测置信度分数阈值**
  - 你还可以提供可选的置信度分数阈值，超过该阈值的检测将传递给匿名器。在 `presidio_score_thresholds` 中没有条目的实体保留所有检测（无最低分数）。
- **作用域**
  - 使用可选的 `presidio_filter_scope` 选择检查运行的位置：

      - `input`：仅扫描用户 → 模型内容
      - `output`：仅扫描模型 → 用户内容
      - `both`（默认）：扫描两个方向

    **`output_parse_pii` 呢？**
    此标志仅在模型调用后将令牌还原为原始值；它不在输出上运行 Presidio 检测。当你希望 Presidio 在模型响应到达用户之前主动扫描和脱敏时，使用 `presidio_filter_scope: output`（或 `both`）。

    **何时选择 input vs output：**
    - `input`：保护上游提供者；在离开你的边界之前剥离个人身份信息(PII)。
    - `output`：捕获模型可能生成或泄露给用户的个人身份信息(PII)。
    - `both`：两个方向的端到端保护。

### 在 `config.yaml` 中配置实体类型、检测置信度分数阈值和作用域

使用特定实体类型配置定义你的护栏：

```yaml title="config.yaml with Entity Types" showLineNumbers
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "presidio-mask-guard"
    openmcp_params:
      guardrail: presidio
      mode: "pre_mcp_call"  # Use this mode for MCP requests
      presidio_filter_scope: both  # input | output | both, optional
      presidio_score_thresholds: # Optional
        ALL: 0.7            # Default confidence threshold applied to all entities
        CREDIT_CARD: 0.8    # Override for credit cards
        EMAIL_ADDRESS: 0.6  # Override for emails
      pii_entities_config:
        CREDIT_CARD: "MASK"  # Will mask credit card numbers
        EMAIL_ADDRESS: "MASK"  # Will mask email addresses
        
  - guardrail_name: "presidio-block-guard"
    openmcp_params:
      guardrail: presidio
      mode: "pre_call"  # Use this mode for regular LLM requests
      presidio_filter_scope: both  # input | output | both, optional
      presidio_score_thresholds: # Optional
        CREDIT_CARD: 0.8  # Only keep credit card detections scoring 0.8+
      pii_entities_config:
        CREDIT_CARD: "BLOCK"  # Will block requests containing credit card numbers
```

#### 置信度阈值行为：
- 无 `presidio_score_thresholds`：保留所有检测（不应用阈值）
- `presidio_score_thresholds.ALL`：对每个检测应用此置信度阈值
- `presidio_score_thresholds.<ENTITY>`：仅对该实体应用
- 如果同时存在 `ALL` 和实体覆盖，`ALL` 全局应用，实体覆盖对该实体优先

### 大内容分块

Presidio analyzer 部署通常限制 `/analyze` 请求体大小（例如 1 MB），分析器延迟随负载大小增长而增加。OpenMCP 会自动将任何序列化 `/analyze` 体超过 `presidio_analyze_chunk_size_bytes`（默认：`500000` 字节，以分析器接收的 JSON 转义形式计量）的单个内容块拆分为重叠的分块，以有限的扇出分析分块，然后将检测合并回原始文本，因此大内容块会被正确脱敏，而不是以 `HTTP 413` 失败。

```yaml
guardrails:
  - guardrail_name: "presidio-pii"
    openmcp_params:
      guardrail: presidio
      mode: "pre_call"
      presidio_analyze_chunk_size_bytes: 500000 # optional, default 500000
```

将其设置为低于你的分析器部署的请求体限制，为分析负载的其余部分（实体列表、临时识别器）留出余量。

### 支持的实体类型

OpenMCP 支持所有 Presidio 实体类型。完整的 presidio 实体类型列表请参见[这里](https://microsoft.github.io/presidio/supported_entities/)。

### 支持的操作

对于每种实体类型，你可以指定以下操作之一：

- `MASK`：将实体替换为占位符（例如 `<PERSON>`）
- `BLOCK`：如果检测到此实体类型，则完全阻止请求

## 高级

### 支持的模式

Presidio 护栏支持以下模式：

- `pre_call`：在大语言模型(LLM)调用**之前**运行，处理**输入**
- `post_call`：在大语言模型(LLM)调用**之后**运行，处理**输入和输出**
- `logging_only`：在大语言模型(LLM)调用**之后**运行，仅在记录到 Langfuse 等之前应用个人身份信息(PII)脱敏。不在实际的 LLM API 请求/响应上运行
- `pre_mcp_call`：在 MCP 调用**之前**运行，处理**输入**。当你想对 MCP 请求应用个人身份信息(PII)脱敏/阻止时使用此模式

### MCP 使用示例

以下是将 Presidio 护栏与 MCP 配合使用的方法：

```yaml title="MCP Configuration Example" showLineNumbers
guardrails:
  - guardrail_name: "presidio-mcp-guard"
    openmcp_params:
      guardrail: presidio
      mode: "pre_mcp_call"
      presidio_filter_scope: both  # input | output | both
      presidio_score_thresholds:
        CREDIT_CARD: 0.8  # Only keep credit card detections scoring 0.8+
        EMAIL_ADDRESS: 0.6  # Only keep email detections scoring 0.6+
      pii_entities_config:
        CREDIT_CARD: "MASK"  # Will mask credit card numbers
        EMAIL_ADDRESS: "BLOCK"  # Will block email addresses
        PHONE_NUMBER: "MASK"  # Will mask phone numbers
        MEDICAL_LICENSE: "BLOCK"  # Will block medical license numbers
      default_on: true
```

使用请求测试 MCP 护栏：

```shell title="Test MCP Guardrail" showLineNumbers
curl http://localhost:4000/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-1234" \
  -d '{
    "model": "{{openai_small}}",
    "messages": [
      {"role": "user", "content": "My credit card is 4111-1111-1111-1111 and my medical license is ABC123"}
    ],
    "guardrails": ["presidio-mcp-guard"]
  }'
```

请求将按以下方式处理：
1. 信用卡号将被脱敏（例如替换为 `<CREDIT_CARD>`）
2. 如果检测到医疗执照，请求将被 `BlockedPiiEntityError` 阻止

#### 支持的语言代码

Presidio 支持多种语言进行个人身份信息(PII)检测。常见语言代码包括：

- `en` - 英语（默认）
- `es` - 西班牙语
- `de` - 德语

完整的支持语言列表请参阅 [Presidio 文档](https://microsoft.github.io/presidio/analyzer/languages/)。

#### 语言优先级

语言设置遵循以下优先级顺序：

1. **按请求语言**（通过 `guardrail_config.language`）- 最高优先级
2. **YAML 配置语言**（通过 `presidio_language`）- 中等优先级
3. **默认语言**（`en`）- 最低优先级

**混合语言示例：**

      guardrail: presidio
      mode: "pre_call"
      presidio_language: "de"  # Default to German
      pii_entities_config:
        CREDIT_CARD: "MASK"
        PERSON: "MASK"

### 输出解析

大语言模型(LLM)响应有时可能包含脱敏令牌。

对于 presidio 的 'replace' 操作，OpenMCP 可以检查大语言模型(LLM)响应并将脱敏令牌替换为用户提交的值。

在 `guardrails` 部分定义你的护栏
```yaml title="Output Parsing Config" showLineNumbers
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "presidio-pre-guard"
    openmcp_params:
      guardrail: presidio  # supported values: "aporia", "bedrock", "lakera", "presidio"
      mode: "pre_call"
      output_parse_pii: True
```

**预期流程：**

1. 用户输入："hello world, my name is Jane Doe. My number is: 034453334"

2. 大语言模型(LLM)输入："hello world, my name is [PERSON]. My number is: [PHONE_NUMBER]"

3. 大语言模型(LLM)响应："Hey [PERSON], nice to meet you!"

4. 用户响应："Hey Jane Doe, nice to meet you!"
