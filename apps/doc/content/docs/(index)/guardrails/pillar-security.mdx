Pillar Security 通过 [Generic Guardrail API](https://www.openmcp.cn/docs/docs/adding_provider/generic_guardrail_api) 与 [OpenMCP Proxy](https://www.openmcp.cn/docs) 集成，为你的 LLM 应用提供 AI 安全扫描。

- **提示词注入防护**：防止恶意提示词操纵
- **越狱检测**：检测绕过 AI 安全措施的尝试
- **PII + PCI 检测**：自动检测敏感的个人和支付卡信息
- **密钥检测**：识别 API 密钥、令牌和凭据
- **内容审核**：过滤有害或不当内容
- **有毒语言**：过滤冒犯性或有害语言

## 快速开始

### 1. 设置环境变量

```bash
export PILLAR_API_KEY=your-pillar-api-key
export OPENAI_API_KEY=your-openai-api-key
```

### 2. 配置 OpenMCP

创建或更新你的 `config.yaml`：

```yaml
model_list:
  - model_name: {{openai_large}}
    openmcp_params:
      model: openai/{{openai_large}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: pillar-security
    openmcp_params:
      guardrail: generic_guardrail_api
      mode: [pre_call, post_call]
      api_base: https://api.pillar.security/api/v1/integrations/openmcp
      api_key: os.environ/PILLAR_API_KEY
      default_on: true
      additional_provider_specific_params:
        plr_mask: true
        plr_evidence: true
        plr_scanners: true
```

<Callout type="warn" title="Important">

- `api_base` 必须正好是 `https://api.pillar.security/api/v1/integrations/openmcp`，这是唯一支持 Generic Guardrail API 集成的端点。
- `guardrail: generic_guardrail_api` 的值不得更改。这是 OpenMCP 内置的护栏类型。不过，你可以将 `guardrail_name` 自定义为你喜欢的任何值。

</Callout>

### 3. 启动 OpenMCP Proxy

```bash
openmcp --config config.yaml --port 4000
```

### 4. 测试集成

```bash
curl -X POST "http://localhost:4000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-master-key" \
  -d '{
    "model": "{{openai_large}}",
    "messages": [{"role": "user", "content": "Hello, how are you?"}]
  }'
```

## 前置条件

开始之前，请确保你已具备：

1. **Pillar Security 账户**：在 [Pillar Dashboard](https://app.pillar.security) 注册
2. **API 凭据**：从仪表板获取你的 API 密钥
3. **OpenMCP Proxy**：安装并配置 OpenMCP 代理

## 护栏模式

Pillar Security 支持三种执行模式：

| 模式 | 运行时机 | 保护内容 | 用例 |
|------|-------------|------------------|----------|
| **`pre_call`** | LLM 调用之前 | 仅用户输入 | 拦截恶意提示词，防止提示词注入 |
| **`during_call`** | 与 LLM 调用并行 | 仅用户输入 | 更低延迟的输入监控 |
| **`post_call`** | LLM 响应之后 | 完整对话上下文 | 输出过滤，检测响应中的 PII/PCI |

### 为什么推荐双模式

<Callout type="info" title="Recommended">

使用 `[pre_call, post_call]` 对输入和输出提供完整保护。

</Callout>

- **完整保护**：同时防护传入的提示词和传出的响应
- **提示词注入防御**：在到达 LLM 之前拦截恶意输入
- **响应监控**：检测输出中的 PII、密钥或不当内容
- **完整上下文分析**：Pillar 可以看到完整对话以实现更好的检测

## 配置参考

### 核心参数

| 参数 | 描述 |
|-----------|-------------|
| `guardrail` | 必须为 `generic_guardrail_api`（不要更改此值） |
| `api_base` | 必须为 `https://api.pillar.security/api/v1/integrations/openmcp`（不要更改此值） |
| `api_key` | Pillar API 密钥（作为 `x-api-key` 头发送） |
| `mode` | 运行时机：`pre_call`、`post_call`、`during_call`，或类似 `[pre_call, post_call]` 的数组 |
| `default_on` | 默认对所有请求启用护栏 |

### Pillar 特定参数

这些参数通过 `additional_provider_specific_params` 传递：

| 参数 | 类型 | 描述 |
|-----------|------|-------------|
| `plr_mask` | bool | 在发送给 LLM 之前启用敏感数据（PII、PCI、密钥）的自动掩码 |
| `plr_evidence` | bool | 在响应中包含检测证据 |
| `plr_scanners` | bool | 在响应中包含扫描器详情 |
| `plr_persist` | bool | 将会话数据持久化到 Pillar 仪表板 |

<Callout type="info">

**启用 `plr_mask: true`** 可在敏感数据（PII、密钥、支付卡信息）到达 LLM 之前自动净化。掩码后的内容会被替换为占位符，而原始数据会保留在 Pillar 的审计日志中。

</Callout>

## 响应详情级别

使用 `plr_scanners` 和 `plr_evidence` 控制响应中包含哪些检测数据：

### 最小响应

当 `plr_scanners` 和 `plr_evidence` 都为 `false` 时：

```json
{
  "session_id": "abc-123",
  "flagged": true
}
```

当你只关心 Pillar 是否检测到威胁时使用。

### 扫描器细分

当 `plr_scanners: true` 时：

```json
{
  "session_id": "abc-123",
  "flagged": true,
  "scanners": {
    "jailbreak": true,
    "prompt_injection": false,
    "pii": false,
    "secret": false,
    "toxic_language": false
  }
}
```

当你需要知道哪些类别被触发时使用。

### 完整上下文

当 `plr_scanners: true` 和 `plr_evidence: true` 都设置时：

```json
{
  "session_id": "abc-123",
  "flagged": true,
  "scanners": {
    "jailbreak": true
  },
  "evidence": [
    {
      "category": "jailbreak",
      "type": "prompt_injection",
      "evidence": "Ignore previous instructions",
      "metadata": { "start_idx": 0, "end_idx": 28 }
    }
  ]
}
```

非常适合调试、审计日志或合规导出。

<Callout type="info">

**始终设置 `plr_scanners: true` 和 `plr_evidence: true`** 以查看 Pillar 检测到的内容。这对于排查问题和理解安全威胁至关重要。

</Callout>

## 会话跟踪

Pillar 使用 OpenMCP 的元数据系统支持会话跟踪：

```bash
curl -X POST "http://localhost:4000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-key" \
  -d '{
    "model": "{{openai_large}}",
    "messages": [{"role": "user", "content": "Hello!"}],
    "user": "user-123",
    "metadata": {
      "pillar_session_id": "conversation-456"
    }
  }'
```

这提供了清晰、明确的对话跟踪，可与 OpenMCP 的会话管理配合使用。
