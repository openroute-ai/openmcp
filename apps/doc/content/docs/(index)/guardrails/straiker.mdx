Straiker 护栏对通过 OpenMCP 路由的流量应用运行时 AI 安全。在每次调用时，它会检查提示词和响应，包括工具定义和工具调用，并可以在内容到达模型或客户端之前进行拦截或脱敏。

Straiker 检测：

- 提示词注入和间接提示词注入，包括隐藏在工具输出中的有效负载
- 工具滥用、数据外泄和远程代码执行尝试
- 提示词和响应中的 PII、凭据、机密和其他敏感数据
- 图像和附件中的多模态攻击

Straiker 根据内容判断调用是否为智能体型，因此没有需要配置的智能体模式。相同的配置覆盖单轮聊天和多轮使用工具的智能体。

## 快速开始

### 1. 获取你的 Straiker API 密钥

在 Straiker 控制台中，打开 **Defend**，点击 **Add Agent**，选择 **OpenMCP Gateway** 磁贴，然后从 **Connect** 步骤复制密钥。

### 2. 将 Straiker 添加到你的 OpenMCP config.yaml

在 `guardrails` 部分下定义护栏。为每个钩子点注册一次，以便提示词和响应都被检查。

```yaml title="config.yaml"
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: straiker-pre
    openmcp_params:
      guardrail: straiker
      mode: pre_call
      default_on: true
      api_key: os.environ/STRAIKER_API_KEY
      unreachable_fallback: fail_closed  # block if Straiker is unreachable

  - guardrail_name: straiker-post
    openmcp_params:
      guardrail: straiker
      mode: post_call
      default_on: true
      api_key: os.environ/STRAIKER_API_KEY
      unreachable_fallback: fail_open  # never withhold a response on an outage
```

在 `pre_call` 上使用 `fail_closed`，这样中断不会让未经筛查的流量到达模型；在 `post_call` 上使用 `fail_open`，这样中断不会扣留模型已经生成的响应。

### 3. 启动 OpenMCP 代理

```shell
export OPENAI_API_KEY=sk-...
export STRAIKER_API_KEY=...
openmcp --config config.yaml
```

## 将调用归属到各个智能体

在请求元数据中设置 `agent_id` 可将调用归属到特定应用程序，设置 `app_name` 可为其提供显示名称。

```shell
curl -sSLX POST 'http://0.0.0.0:4000/v1/chat/completions' \
--header 'Content-Type: application/json' \
--data '{
  "model": "{{openai_small}}",
  "messages": [{"role": "user", "content": "Refund order 12345"}],
  "metadata": {
    "agent_id": "payments-agent",
    "app_name": "Payments Copilot",
    "session_id": "session-abc"
  }
}'
```

使用集合范围的 API 密钥时，每个不同的 `agent_id` 都会在 Straiker 控制台中作为自己的应用程序被发现，因此一个网关面对多个智能体时无需额外配置即可生成按智能体划分的清单。应用程序范围的密钥会将每次调用固定到单个应用程序，无论 `agent_id` 如何。没有 `agent_id` 的调用会归属到 `default_app`。

调用方身份取自 OpenMCP 自己的密钥、团队和用户记录，因此使用别名和用户创建虚拟密钥会自动归属每次调用。OpenAI 的 `user` 字段会作为代表其发起调用的最终用户被传递。

## 支持的参数

`api_key` 是必需的。没有环境变量回退，因此请在配置中设置它。

| 参数 | 默认值 | 描述 |
|---|---|---|
| `api_base` | `https://api.prod.straiker.ai` | 仅主机。检测路径会自动附加。对于非美国租户，请将其设置为你的区域 |
| `default_app` | `OpenMCP Gateway` | 当调用不携带 `agent_id` 时使用的应用程序名称。也接受为 `source` |
| `timeout` | `5.0` | 每次尝试的 HTTP 超时（秒） |
| `max_retries` | `2` | 在 HTTP 408、429、500、502、503、504 和网络错误时的重试次数 |
| `initial_backoff` | `0.1` | 首次重试退避（秒） |
| `max_backoff` | `2.0` | 退避上限（秒） |
| `unreachable_fallback` | `fail_closed` | 重试后仍无法到达 Straiker 时的行为 |
| `fail_on_error` | `true` | Straiker 的非成功响应是否拦截调用 |
| `max_payload_bytes` | `524288` | 序列化有效负载的最大大小 |
| `custom_headers` | `None` | 发送到 Straiker 的附加请求头。`Authorization` 不能被覆盖 |
| `metadata` | `None` | 应用于每次调用的元数据。键冲突时配置值优先 |
| `verbose` | `false` | 在拦截响应中包含完整的按类别检测信封 |
| `streaming_buffer_until_moderated` | `true` | 扣留每个流式分块直到流结束审核通过，因此任何被标记的分块都不会在拦截之前到达客户端 |
| `streaming_end_of_stream_only` | `true` | 仅对组装后的响应评估一次流式输出 |
| `streaming_sampling_rate` | `5` | 不缓冲时，每隔第 N 个流式分块进行评估。必须至少为 1 |

## 支持的模式

Straiker 支持 `pre_call` 和 `post_call`，两者都可以拦截。`during_call` 在初始化时会被拒绝。

流式响应在 `post_call` 上处理。默认情况下，流会被缓冲，直到组装后的响应完成审核，因此任何被标记的分块都不会在拦截之前到达客户端。要以此安全换取更低的延迟，请将 `streaming_buffer_until_moderated` 设置为 `false`，并使用 `streaming_sampling_rate` 在分块流式传输时进行评估。
