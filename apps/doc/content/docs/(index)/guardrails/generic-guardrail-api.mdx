## 问题

作为护栏(guardrail)提供者，集成 OpenMCP 通常需要：
- 向 OpenMCP 仓库提交 PR
- 等待审核和合并
- 在 OpenMCP 代码库中维护提供者特定的代码
- 为 API 变更更新集成

## 解决方案

**通用护栏 API** 让你通过实现一个简单的 API 端点即可**即时**集成 OpenMCP。无需 PR。

### 核心优势

1. **无需 PR** - 立即部署和集成
2. **通用支持** - 适用于所有 OpenMCP 端点（chat、embeddings、图像生成等）
3. **简单契约** - 一个端点，三种响应类型
4. **多模态支持** - 处理请求/响应中的文本和图像
5. **自定义参数** - 通过配置传递提供者特定参数
6. **完全控制** - 你拥有并维护自己的护栏 API

## 支持的端点

通用护栏 API 适用于以下 OpenMCP 端点：

- `/v1/chat/completions` - OpenAI Chat Completions
- `/v1/completions` - OpenAI Text Completions
- `/v1/responses` - OpenAI Responses API
- `/v1/images/generations` - OpenAI Image Generation
- `/v1/audio/transcriptions` - OpenAI Audio Transcriptions
- `/v1/audio/speech` - OpenAI Text-to-Speech
- `/v1/messages` - Anthropic Messages
- `/v1/rerank` - Cohere Rerank
- 透传端点

## 工作原理

1. OpenMCP 从任何请求中提取文本和图像（chat 消息、embeddings、图像提示等）
2. 将提取的内容 + 元数据发送到你的 API 端点
3. 你的 API 响应：`BLOCKED`、`NONE` 或 `GUARDRAIL_INTERVENED`
4. OpenMCP 执行决策并应用任何修改

## API 契约

### 端点

实现 `POST /beta/openmcp_basic_guardrail_api`

### 请求格式

```json
{
  "texts": ["extracted text from the request"],  // array of text strings
  "images": ["base64_encoded_image_data"],  // optional array of images
  "tools": [  // tool calls sent to the LLM (in the OpenAI Chat Completions spec)
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get the current weather",
        "parameters": {
          "type": "object",
          "properties": {
            "location": {"type": "string"}
          }
        }
      }
    }
  ],
  "tool_calls": [  // tool calls received from the LLM (in the OpenAI Chat Completions spec)
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "get_weather",
        "arguments": "{\"location\": \"San Francisco\"}"
      }
    }
  ],
  "structured_messages": [  // optional, full messages in OpenAI format (for chat endpoints)
    {"role": "system", "content": "You are a helpful assistant"},
    {"role": "user", "content": "Hello"}
  ],
  "request_data": {
    "user_api_key_hash": "hash of the openmcp virtual key used",
    "user_api_key_alias": "alias of the openmcp virtual key used",
    "user_api_key_user_id": "user id associated with the openmcp virtual key used",
    "user_api_key_user_email": "user email associated with the openmcp virtual key used",
    "user_api_key_team_id": "team id associated with the openmcp virtual key used",
    "user_api_key_team_alias": "team alias associated with the openmcp virtual key used",
    "user_api_key_end_user_id": "end user id associated with the openmcp virtual key used",
    "user_api_key_org_id": "org id associated with the openmcp virtual key used"
  },
  "request_headers": {  // optional: inbound request headers (allowlist). Allowed headers show their value; all others show "[present]" to indicate the header existed.
    "User-Agent": "OpenAI/Python 2.17.0",
    "Content-Type": "application/json",
    "X-Request-Id": "[present]"
  },
  "openmcp_version": "1.x.y",  // optional: OpenMCP library version running this proxy
  "input_type": "request",  // "request" or "response"
  "openmcp_call_id": "unique_call_id",  // the call id of the individual LLM call
  "openmcp_trace_id": "trace_id",  // the trace id of the LLM call - useful if there are multiple LLM calls for the same conversation
  "additional_provider_specific_params": {
    // your custom params from config
  }
}
```

### 响应格式

```json nolint
{
  "action": "BLOCKED" | "NONE" | "GUARDRAIL_INTERVENED",
  "blocked_reason": "why content was blocked",  // required if action=BLOCKED
  "texts": ["modified text"],  // optional array of modified text strings
  "images": ["modified_base64_image"]  // optional array of modified images
}
```

**操作：**
- `BLOCKED` - OpenMCP 抛出错误并阻止请求
- `NONE` - 请求继续不变
- `GUARDRAIL_INTERVENED` - 请求继续并使用修改后的文本/图像（提供 `texts` 和/或 `images` 字段）

## 参数

### `tools` 参数

`tools` 参数提供请求中可用的函数/工具定义信息。

**格式：** OpenAI `ChatCompletionToolParam` 格式（参见 [OpenAI API 参考](https://platform.openai.com/docs/api-reference/chat/create#chat-create-tools)）

仅包含 `type` 而没有 `function` 块的内置工具（如 `{"type": "code_interpreter"}` 或 `{"type": "file_search", "vector_store_ids": [...]}`）也会被接受并原样转发到你的端点（包括其工具特定配置）。你的端点应将 `function` 视为可选，并根据 `type` 进行分支。

**示例：**
```json
{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "Get the current weather in a location",
    "parameters": {
      "type": "object",
      "properties": {
        "location": {
          "type": "string",
          "description": "City and state, e.g. San Francisco, CA"
        },
        "unit": {
          "type": "string",
          "enum": ["celsius", "fahrenheit"]
        }
      },
      "required": ["location"]
    }
  }
}
```

**可用性：**
- **仅输入：** 工具仅在 `input_type="request"`（调用前护栏）时传递。输出/响应护栏当前不接收工具定义。
- **支持的端点：** `tools` 参数在以下端点受支持：`/v1/chat/completions`、`/v1/responses` 和 `/v1/messages`。其他端点不支持工具。

**用例：**
- 执行工具权限策略（例如仅允许特定用户/团队访问特定工具）
- 在发送到大语言模型(LLM)之前验证工具 schema
- 记录工具使用情况以供审计
- 根据用户上下文阻止敏感工具

### `tool_calls` 参数

`tool_calls` 参数包含请求或响应中实际执行的函数/工具调用。

**格式：** OpenAI `ChatCompletionMessageToolCall` 格式（参见 [OpenAI API 参考](https://platform.openai.com/docs/api-reference/chat/object#chat/object-tool_calls)）

**示例：**
```json
{
  "id": "call_abc123",
  "type": "function",
  "function": {
    "name": "get_weather",
    "arguments": "{\"location\": \"San Francisco\", \"unit\": \"celsius\"}"
  }
}
```

**与 `tools` 的关键区别：**
- **`tools`** = 工具定义/schema（哪些工具*可用*）
- **`tool_calls`** = 工具调用/执行（哪些工具*正在被调用*及使用什么参数）

**可用性：**
- **输入和输出均适用：** 工具调用可同时出现在 `input_type="request"`（助手消息请求工具调用）和 `input_type="response"`（大语言模型(LLM)响应包含工具调用）中。
- **支持的端点：** `tool_calls` 参数在以下端点受支持：`/v1/chat/completions`、`/v1/responses` 和 `/v1/messages`。

**用例：**
- 在执行前验证工具调用参数
- 编辑工具调用参数中的敏感数据（例如个人身份信息(PII)）
- 记录工具调用以供审计/调试
- 阻止包含危险参数的工具调用
- 修改工具调用参数（例如执行约束、清理输入）
- 监控跨用户/团队的工具使用模式

### `structured_messages` 参数

`structured_messages` 参数以 OpenAI chat completion spec 格式提供完整的输入，有助于区分系统消息和用户消息。

**格式：** OpenAI chat completion 消息数组（参见 [OpenAI API 参考](https://platform.openai.com/docs/api-reference/chat/create#chat-create-messages)）

**示例：**
```json
[
  {"role": "system", "content": "You are a helpful assistant"},
  {"role": "user", "content": "Hello"}
]
```

**可用性：**
- **支持的端点：** `/v1/chat/completions`、`/v1/messages`、`/v1/responses`
- **仅输入：** 仅在 `input_type="request"`（调用前护栏）时传递

**用例：**
- 对系统消息和用户消息应用不同策略
- 执行基于角色的内容限制
- 记录结构化的对话上下文

## OpenMCP 配置

添加到 `config.yaml`：

```yaml
openmcp_settings:
  guardrails:
    - guardrail_name: "my-guardrail"
      openmcp_params:
        guardrail: generic_guardrail_api
        mode: pre_call  # or post_call, during_call
        api_base: https://your-guardrail-api.com
        api_key: os.environ/YOUR_GUARDRAIL_API_KEY  # optional
        unreachable_fallback: fail_closed  # default: fail_closed. Set to fail_open to proceed if the guardrail endpoint is unreachable (network errors, or HTTP 502/503/504 from an upstream proxy/LB).
        fail_on_error: true  # default: true (fail closed). Set to false to proceed on ANY guardrail error. See "Error handling" below before changing this.
        additional_provider_specific_params:
          # your custom parameters
          threshold: 0.8
          language: "en"
```

### 错误处理：`unreachable_fallback` 和 `fail_on_error`

两个设置控制当护栏本身失败（而非返回裁定）时 OpenMCP 的行为。它们处于严格到宽松的频谱上，且可组合使用：

- `unreachable_fallback`（默认 `fail_closed`）仅在护栏端点**不可达**时生效：网络错误、超时或来自上游代理/负载均衡器的 HTTP 502/503/504。将其设置为 `fail_open` 以在这些情况下允许请求继续。
- `fail_on_error`（默认 `true`）是更广泛的控制。它管理**任何**护栏错误，而不仅仅是不可达。

| `fail_on_error` | 护栏错误时的行为 |
| --- | --- |
| `true`（默认） | **失败关闭。** 任何错误都会阻止请求：非 2xx 响应、格式错误或无法解析的响应体、网络故障或内部序列化/验证错误。这保留了 OpenMCP 的现有行为 |
| `false` | **完全失败开放。** 任何护栏错误都降级为关键级别日志行，请求继续，如同护栏未配置 |

只有有效的护栏响应才能执行操作。使用 `fail_on_error: false` 时，已解析的 `BLOCKED` 决策仍然会阻止；所有不是有效响应的内容（错误、格式错误的响应体、不可达的端点）都会被绕过。这适用于请求钩子（`pre_call`）和响应钩子（`post_call`）；在响应路径上，失败开放返回已生成的模型输出，而失败关闭则将成功的生成变为错误。

<Callout type="error">

`fail_on_error: false` 是失败时的完全绕过。这意味着护栏或其端点中**任何**原因的失败都会导致该请求跳过护栏，而不是阻止它。仅在你理解并接受此权衡后才启用它：当你的可用性和运营约束强于安全约束时选择它。如果护栏是硬安全边界，请保持默认的 `true`（失败关闭）。

</Callout>

默认设置为失败关闭，正是因为护栏通常是安全控制。每次失败开放的绕过都会以关键级别记录（`Generic Guardrail API error (fail-open) ...`），并包含调用 ID 和追踪 ID，以便你进行告警和审计其发生频率。

### 静态和动态头部

你可以向护栏端点发送两种类型的头部：

- **静态头部**（`headers`）：一个键/值映射，**每个**发送到护栏的请求都会携带。用于固定值（例如 API 密钥、`X-Service-Name`）。在 `openmcp_params` 中配置：

  ```yaml
  openmcp_params:
    guardrail: generic_guardrail_api
    api_base: https://your-guardrail-api.com
    headers:
      X-Service-Name: "my-app"
      X-API-Key: "secret"
  ```

- **动态头部**（`extra_headers`）：一个**头部名称**列表，从**客户端请求**转发到你的护栏。只有此列表中的头部（加上一个小的默认允许列表如 `x-openmcp-*`）才会发送其值；其他头部发送为 `[present]`。用于传递客户端提供的头部（例如 `x-request-id`、`x-correlation-id`）。在 `openmcp_params` 中配置：

  ```yaml
  openmcp_params:
    guardrail: generic_guardrail_api
    api_base: https://your-guardrail-api.com
    extra_headers:
      - x-request-id
      - x-correlation-id
      - x-custom-auth
  ```

这与 [MCP 静态和额外头部](/docs/mcp#forwarding-custom-headers-to-mcp-servers)行为一致。

### 示例：Pillar Security

[Pillar Security](https://pillar.security) 使用通用护栏 API 提供 AI 安全扫描，包括提示词注入保护、个人身份信息(PII)/PCI 检测、密钥检测和内容审核。

```yaml
guardrails:
  - guardrail_name: "pillar-security"
    openmcp_params:
      guardrail: generic_guardrail_api
      mode: [pre_call, post_call]
      api_base: https://api.pillar.security/api/v1/integrations/openmcp
      api_key: os.environ/PILLAR_API_KEY
      default_on: true
      additional_provider_specific_params:
        plr_mask: true      # Enable automatic masking of sensitive data
        plr_evidence: true  # Include detection evidence in response
        plr_scanners: true  # Include scanner details in response
```

完整配置选项请参见 [Pillar Security 文档](/docs/guardrails/pillar-security)。

## 使用方法

用户通过名称应用你的护栏：

```python
response = client.chat.completions.create(
    model="{{openai_large}}",
    messages=[{"role": "user", "content": "hello"}],
    guardrails=["my-guardrail"]
)
```

或使用动态参数：

```python
response = client.chat.completions.create(
    model="{{openai_large}}",
    messages=[{"role": "user", "content": "hello"}],
    guardrails=[{
        "my-guardrail": {
            "extra_body": {
                "custom_threshold": 0.9
            }
        }
    }]
)
```

## 实现示例

参见 [mock_bedrock_guardrail_server.py](https://github.com/BerriAI/openmcp/blob/main/cookbook/mock_guardrail_server/mock_bedrock_guardrail_server.py) 获取完整参考实现。

**最小 FastAPI 示例：**

```python
from fastapi import FastAPI
from pydantic import BaseModel
from typing import List, Optional, Dict, Any

app = FastAPI()

class GuardrailRequest(BaseModel):
    texts: List[str]
    images: Optional[List[str]] = None
    tools: Optional[List[Dict[str, Any]]] = None  # OpenAI ChatCompletionToolParam format (tool definitions)
    tool_calls: Optional[List[Dict[str, Any]]] = None  # OpenAI ChatCompletionMessageToolCall format (tool invocations)
    structured_messages: Optional[List[Dict[str, Any]]] = None  # OpenAI messages format (for chat endpoints)
    request_data: Dict[str, Any]
    input_type: str  # "request" or "response"
    openmcp_call_id: Optional[str] = None
    openmcp_trace_id: Optional[str] = None
    additional_provider_specific_params: Dict[str, Any]

class GuardrailResponse(BaseModel):
    action: str  # BLOCKED, NONE, or GUARDRAIL_INTERVENED
    blocked_reason: Optional[str] = None
    texts: Optional[List[str]] = None
    images: Optional[List[str]] = None

@app.post("/beta/openmcp_basic_guardrail_api")
async def apply_guardrail(request: GuardrailRequest):
    # Your guardrail logic here
    
    # Example: Check text content
    for text in request.texts:
        if "badword" in text.lower():
            return GuardrailResponse(
                action="BLOCKED",
                blocked_reason="Content contains prohibited terms"
            )
    
    # Example: Check tool definitions (if present in request)
    if request.tools:
        for tool in request.tools:
            if tool.get("type") == "function":
                function_name = tool.get("function", {}).get("name", "")
                # Block sensitive tool definitions
                if function_name in ["delete_data", "access_admin_panel"]:
                    return GuardrailResponse(
                        action="BLOCKED",
                        blocked_reason=f"Tool '{function_name}' is not allowed"
                    )
    
    # Example: Check tool calls (if present in request or response)
    if request.tool_calls:
        for tool_call in request.tool_calls:
            if tool_call.get("type") == "function":
                function_name = tool_call.get("function", {}).get("name", "")
                arguments_str = tool_call.get("function", {}).get("arguments", "{}")
                
                # Parse arguments and validate
                import json
                try:
                    arguments = json.loads(arguments_str)
                    # Block dangerous arguments
                    if "file_path" in arguments and ".." in str(arguments["file_path"]):
                        return GuardrailResponse(
                            action="BLOCKED",
                            blocked_reason="Tool call contains path traversal attempt"
                        )
                except json.JSONDecodeError:
                    pass
    
    # Example: Check structured messages (if present in request)
    if request.structured_messages:
        for message in request.structured_messages:
            if message.get("role") == "system":
                # Apply stricter policies to system messages
                if "admin" in message.get("content", "").lower():
                    return GuardrailResponse(
                        action="BLOCKED",
                        blocked_reason="System message contains restricted terms"
                    )
    
    return GuardrailResponse(action="NONE")
```

## 何时使用

✅ **在以下情况使用通用护栏 API：**
- 你想即时集成，无需等待 PR
- 你维护自己的护栏服务
- 你需要完全控制更新和功能
- 你想自动支持所有 OpenMCP 端点

❌ **在以下情况提交 PR：**
- 你想更深入地集成 OpenMCP 内部机制
- 你的护栏需要复杂的 OpenMCP 特定逻辑
- 你想成为内置提供者
