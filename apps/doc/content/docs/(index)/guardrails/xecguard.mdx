使用 [XecGuard](https://www.cycraft.com/)（CyCraft）通过多策略扫描（提示词注入、有害内容、PII、系统提示词强制执行、技能保护）和 RAG 上下文依据性验证来保护你的 LLM 应用程序。XecGuard 是一个云托管 AI 安全网关，因此没有自托管要求。

## 快速开始

### 1. 在 OpenMCP config.yaml 中定义护栏

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: {{openai_large}}
    openmcp_params:
      model: openai/{{openai_large}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "xecguard-guard"
    openmcp_params:
      guardrail: xecguard
      mode: "pre_call"
      api_key: os.environ/XECGUARD_API_KEY
      api_base: os.environ/XECGUARD_API_BASE   # Optional
      policy_names:                             # Optional — defaults to System Prompt Enforcement + Harmful Content Protection
        - Default_Policy_SystemPromptEnforcement
        - Default_Policy_HarmfulContentProtection
```

#### `mode` 支持的值

- `pre_call` — 在 LLM 调用**之前**运行，以验证**用户输入**
- `post_call` — 在 LLM 调用**之后**运行，以验证**模型输出**（当提供 RAG 文档时还会运行上下文依据性）
- `during_call` — 与 LLM 调用**并行**运行，用于输入验证
- `logging_only` — 作为**仅观察**回调运行；记录扫描决定而不拦截

### 2. 设置环境变量

```shell
export XECGUARD_API_KEY="xgs_<your-service-token>"
export XECGUARD_API_BASE="https://api-xecguard.cycraft.ai"   # Optional, this is the default
export XECGUARD_BLOCK_ON_ERROR="true"                        # Optional, fail-closed by default
```

### 3. 启动 OpenMCP 网关

```shell
openmcp --config config.yaml --detailed_debug
```

## 支持的参数

```yaml
guardrails:
  - guardrail_name: "xecguard-guard"
    openmcp_params:
      guardrail: xecguard
      mode: "pre_call"
      api_key: os.environ/XECGUARD_API_KEY
      api_base: os.environ/XECGUARD_API_BASE       # Optional
      xecguard_model: "xecguard_v2"                 # Optional
      policy_names:                                 # Optional
        - Default_Policy_SystemPromptEnforcement
        - Default_Policy_HarmfulContentProtection
      block_on_error: true                          # Optional
      grounding_strictness: "BALANCED"              # Optional
      default_on: true                              # Optional
```

### 必需

| 参数 | 描述 |
|-----------|-------------|
| `api_key` | XecGuard **Service Token**（前缀 `xgs_`）。回退到 `XECGUARD_API_KEY` 环境变量。 |

### 可选

| 参数 | 默认值 | 描述 |
|-----------|---------|-------------|
| `api_base` | `https://api-xecguard.cycraft.ai` | XecGuard API 基础 URL。回退到 `XECGUARD_API_BASE` 环境变量。 |
| `xecguard_model` | `xecguard_v2` | XecGuard 扫描模型标识符。 |
| `policy_names` | `["Default_Policy_SystemPromptEnforcement", "Default_Policy_HarmfulContentProtection"]` | 每次扫描应用的策略。请参阅下方的[可用策略](#available-policies)。 |
| `block_on_error` | `true` | 默认故障关闭。设置为 `false` 以实现故障开放行为（当 XecGuard API 不可达时请求通过）。 |
| `grounding_strictness` | `BALANCED` | `BALANCED` 或 `STRICT`。控制 `/grounding` 端点评估响应相对于所提供上下文文档的保真度的严格程度。 |
| `default_on` | `false` | 当为 `true` 时，护栏会在每个请求上运行，而无需在请求体中指定它。 |

## 可用策略

XecGuard 附带六个内置默认策略。通过 `policy_names` 选择一个或多个：

| 策略名称 | 用途 |
|-------------|---------|
| `Default_Policy_SystemPromptEnforcement` | 确保用户提示词保持在系统提示词定义的任务范围内 |
| `Default_Policy_GeneralPromptAttackProtection` | 检测提示词注入、提示词提取、编码绕过尝试 |
| `Default_Policy_ContentBiasProtection` | 检测歧视、骚扰、有害刻板印象 |
| `Default_Policy_HarmfulContentProtection` | 检测违反公共秩序和善良风俗的有害言论/语义 |
| `Default_Policy_SkillsProtection` | 检测 AI 智能体技能文件中的恶意内容 |
| `Default_Policy_PIISensitiveDataProtection` | 检测个人身份信息（PII） |

<Callout type="info">

通配符形式 `policy_names: ["*"]` 受 XecGuard API 支持，但要求你的 Service Token 已在 XecGuard 控制台中预先绑定到至少一个策略。

</Callout>

## 上下文依据性（RAG）

在 `post_call` 模式下扫描时，XecGuard 还可以通过 `/grounding` 端点根据参考文档验证助手的响应。这可以捕获 RAG 应用程序中的幻觉和事实漂移。

在请求时通过 `metadata.xecguard_grounding_documents` 字段提供依据性文档。每个文档是 `{document_id, context}`：

```shell
curl -i http://0.0.0.0:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "{{openai_large}}",
    "messages": [
      {"role": "user", "content": "What nationality was Peggy Seeger?"}
    ],
    "guardrails": ["xecguard-guard"],
    "metadata": {
      "xecguard_grounding_documents": [
        {
          "document_id": "peggy_seeger_bio",
          "context": "Peggy Seeger (born June 17, 1935) is an American folk singer."
        }
      ]
    }
  }'
```

如果助手的响应与所提供的文档矛盾或不受其支持，请求会被以依据性违规拦截（`CONFLICT`、`BASELESS` 或 `INCOMPLETE`）：

```json
{
  "error": {
    "message": "Blocked by XecGuard grounding: rules=[CONFLICT] trace_id=fabcde7890123456abcdef1234567829 rationale=Response states Peggy Seeger was British, but the document indicates she is American.",
    "type": "None",
    "param": "None",
    "code": "400"
  }
}
```

依据性仅在以下情况运行：
- `mode` 包含 `post_call`
- `metadata.xecguard_grounding_documents` 是非空列表
- 消息同时包含用户提示词和助手响应

## 高级配置

### 故障开放模式

默认情况下，XecGuard 以**故障关闭**模式运行：如果 API 不可达，请求会被拦截。设置 `block_on_error: false` 可在护栏 API 失败时允许请求通过：

```yaml
guardrails:
  - guardrail_name: "xecguard-failopen"
    openmcp_params:
      guardrail: xecguard
      mode: "pre_call"
      api_key: os.environ/XECGUARD_API_KEY
      block_on_error: false
```

### 输入 + 输出流水线

为一个护栏应用输入验证，另一个用于输出扫描 + 依据性：

```yaml
guardrails:
  - guardrail_name: "xecguard-input"
    openmcp_params:
      guardrail: xecguard
      mode: "pre_call"
      api_key: os.environ/XECGUARD_API_KEY
      policy_names:
        - Default_Policy_GeneralPromptAttackProtection
        - Default_Policy_SystemPromptEnforcement

  - guardrail_name: "xecguard-output"
    openmcp_params:
      guardrail: xecguard
      mode: "post_call"
      api_key: os.environ/XECGUARD_API_KEY
      policy_names:
        - Default_Policy_HarmfulContentProtection
        - Default_Policy_PIISensitiveDataProtection
      grounding_strictness: "STRICT"
```

### 始终开启的防护

为每个请求启用护栏，而无需按调用指定：

```yaml
guardrails:
  - guardrail_name: "xecguard-guard"
    openmcp_params:
      guardrail: xecguard
      mode: "pre_call"
      api_key: os.environ/XECGUARD_API_KEY
      default_on: true
```

### 仅日志模式

观察扫描决定而不拦截，这有助于在强制执行之前进行影子模式部署：

```yaml
guardrails:
  - guardrail_name: "xecguard-monitor"
    openmcp_params:
      guardrail: xecguard
      mode: "logging_only"
      api_key: os.environ/XECGUARD_API_KEY
```

扫描结果会附加到标准日志负载（`standard_logging_guardrail_information`）并显示在 Langfuse / DataDog / OTEL 中，而绝不会拦截请求。

## 完整对话历史

XecGuard 在输入和响应扫描时始终接收**完整对话历史**（系统、用户和助手消息）。这是 `Default_Policy_SystemPromptEnforcement` 等策略正常工作的必要条件。没有配置选项可以禁用此行为；框架范围的 `skip_system_message_in_guardrail` 设置对 XecGuard 有意忽略。

## 错误处理

**缺少 API 凭据：**
```
XecGuardMissingCredentials: XecGuard API key is required.
Set XECGUARD_API_KEY in the environment or pass api_key in the guardrail config.
```

**API 不可达（故障关闭，默认）：**
请求被拦截并抛出 `GuardrailRaisedException`。

**API 不可达（故障开放，`block_on_error: false`）：**
请求原样通过，并记录警告。
