使用 [RepelloAI Argus](https://repello.ai/) 根据你在 Repello 仪表板中按资产配置的策略扫描提示词和响应。Argus 是一个云托管 API；提示词在 `pre_call` 时扫描，模型响应在 `post_call` 时扫描，请求所执行的策略来自你将护栏指向的资产。

## 概述

| 属性 | 详情 |
|----------|---------|
| 描述 | 用于提示词和响应策略执行的云托管护栏 |
| 提供商 | [RepelloAI](https://repello.ai/) |
| 支持的操作 | `BLOCK`（blocked 判定）；`LOG` 警告（flagged 判定） |
| 支持的模式 | `pre_call`、`post_call` |
| 流式传输支持 | 是 |
| API 要求 | Repello API 密钥和资产 ID |

## 前置条件

在配置护栏之前，你需要从 [https://platform.repello.ai/](https://platform.repello.ai/) 的 Repello 仪表板获取两样东西：

- **API 密钥** — 前往你的账户设置并生成 API 密钥。将其设置为环境中的 `ARGUS_API_KEY`。
- **资产 ID** — 在仪表板中创建资产并配置你要执行的策略。复制资产 ID；这就是你在配置中作为 `asset_id` 传递的内容。

策略（拦截什么、标记什么、阈值）完全在仪表板中按资产进行管理。OpenMCP 配置只指向一个资产；它不会内联定义策略。

## 快速开始

### 1. 在 OpenMCP config.yaml 中定义护栏

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: {{openai_large}}
    openmcp_params:
      model: openai/{{openai_large}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: "repelloai-guard"
    openmcp_params:
      guardrail: repelloai
      mode: "pre_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
      api_base: os.environ/REPELLOAI_API_BASE   # Optional
```

#### `mode` 支持的值

- `pre_call` 在 LLM 调用**之前**运行，用于扫描请求文本
- `post_call` 在 LLM 调用**之后**运行，用于扫描模型输出

### 2. 设置环境变量

```shell
export ARGUS_API_KEY="your-argus-api-key"
export REPELLOAI_API_BASE="https://argusapi.repello.ai/sdk/v1"   # Optional, this is the default
```

### 3. 启动 OpenMCP 网关

```shell
openmcp --config config.yaml --detailed_debug
```

## Argus 扫描的内容

RepelloAI 会扫描它在请求体中找到的可检查文本：

- Chat Completions `messages`（所有角色）
- Responses API `input` 条目，包括 `input_text` 内容部分
- Responses API `instructions` 字段
- 旧版 `prompt` 字段（completions API）
- 消息和 Responses API 输出中的工具调用参数（`tool_calls[*].function.arguments`）
- 工具和函数定义（`tools[*].function` schema 文本：名称、描述、枚举值）
- `content` 列表中的多模态文本部分
- 从 chat completions 和 Responses API 请求返回的助手输出

使用 `mode: pre_call` 配置的护栏会检查完整的提示词文本（消息、指令、工具定义和工具调用参数）。`mode: post_call` 会检查助手消息内容、Responses API 输出文本以及模型响应中的任何工具调用参数。

## 流式传输支持

RepelloAI 通过缓冲流、分析完成的助手文本，然后执行以下操作之一来支持 `post_call` 流式流程：

- 当输出被允许时返回原始分块
- 当输出被拦截时抛出流式回调错误

被标记的响应会被允许，但 OpenMCP 会记录警告，因此策略命中在操作员日志中仍然可见。

## 支持的参数

```yaml
guardrails:
  - guardrail_name: "repelloai-guard"
    openmcp_params:
      guardrail: repelloai
      mode: "pre_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
      api_base: os.environ/REPELLOAI_API_BASE   # Optional
      unreachable_fallback: "fail_closed"       # Optional
      default_on: true                           # Optional
```

### 必需

| 参数 | 描述 |
|-----------|-------------|
| `asset_id` | 其仪表板策略会被执行的 Repello 资产。在 Repello 仪表板中创建资产并将其 ID 复制到这里。 |
| `api_key` | Repello API 密钥。回退到环境中的 `ARGUS_API_KEY` 或旧版 `REPELLOAI_API_KEY`。 |

### 可选

| 参数 | 默认值 | 描述 |
|-----------|---------|-------------|
| `api_base` | `https://argusapi.repello.ai/sdk/v1` | Argus API 基础 URL。回退到环境中的 `REPELLOAI_API_BASE`。 |
| `unreachable_fallback` | `fail_closed` | Argus API 不可达时的行为。`fail_closed` 拦截请求；`fail_open` 记录警告并允许请求通过。 |
| `default_on` | `false` | 当为 `true` 时，护栏会在每个请求上运行，而无需在请求体中指定它。 |

## 判定

Argus 每次扫描返回三种判定之一：

- `passed` 请求被允许
- `flagged` 请求被允许，OpenMCP 记录带有违规策略的警告
- `blocked` 请求以 HTTP 400 被拦截，并列出违规策略

无法识别或缺失的判定会被视为 `blocked`，因此上游 schema 变更无法静默地禁用执行。

## 高级配置

### 故障开放模式

默认情况下护栏是**故障关闭**的；如果 Argus 不可达，请求会被拦截。设置 `unreachable_fallback: fail_open` 可在 API 失败时让请求通过：

```yaml
guardrails:
  - guardrail_name: "repelloai-failopen"
    openmcp_params:
      guardrail: repelloai
      mode: "pre_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
      unreachable_fallback: "fail_open"
```

认证和配置错误（HTTP 400/401/403/404/422）无论 `unreachable_fallback` 如何都始终拦截，因为永久错误配置的护栏绝不应静默地放行流量。

### 输入 + 输出流水线

在入口处扫描提示词，在出口处扫描响应。你可以使用单个 `mode` 设置为列表的护栏条目，或两个指向同一资产的单独条目：

```yaml
guardrails:
  - guardrail_name: "repelloai-guard"
    openmcp_params:
      guardrail: repelloai
      mode: ["pre_call", "post_call"]
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
```

或者等效地使用两个条目：

```yaml
guardrails:
  - guardrail_name: "repelloai-input"
    openmcp_params:
      guardrail: repelloai
      mode: "pre_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY

  - guardrail_name: "repelloai-output"
    openmcp_params:
      guardrail: repelloai
      mode: "post_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
```

### 始终开启的防护

为每个请求启用护栏，而无需按调用指定：

```yaml
guardrails:
  - guardrail_name: "repelloai-guard"
    openmcp_params:
      guardrail: repelloai
      mode: "pre_call"
      asset_id: "your-repello-asset-id"
      api_key: os.environ/ARGUS_API_KEY
      default_on: true
```

## 错误处理

**缺少 API 凭据：**
```
RepelloAIGuardrailMissingSecrets: Couldn't get Repello API key.
Set `ARGUS_API_KEY` in the environment or pass `api_key` to the guardrail in the config file.
```

**缺少 asset_id：**
```
ValueError: Repello guardrail requires an `asset_id`. Create an asset in the Repello
dashboard and set `asset_id` on the guardrail in the config file.
```

**API 不可达（故障关闭，默认）：**
请求以 HTTP 500 被拦截。

**API 不可达（故障开放，`unreachable_fallback: fail_open`）：**
请求原样通过，并记录警告。
