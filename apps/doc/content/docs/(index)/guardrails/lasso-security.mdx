使用 [Lasso Security](https://www.lasso.security/) 通过输入和输出验证保护你的 LLM 应用免受提示词注入攻击、有害内容生成及其他安全威胁。

## 前置条件

Lasso 护栏需要 `ulid-py` 包（1.1.0 或更高版本）来生成唯一会话标识符：

```shell
uv add ulid-py>=1.1.0
```

该包用于创建可按字典序排序的标识符，以便在 Lasso Security 平台中跟踪对话和会话。

## 快速开始

### 1. 在 OpenMCP config.yaml 中定义护栏

在 `guardrails` 部分下定义你的护栏：

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: claude-3.5
    openmcp_params:
      model: anthropic/claude-3.5
      api_key: os.environ/ANTHROPIC_API_KEY

guardrails:
  - guardrail_name: "lasso-pre-guard"
    openmcp_params:
      guardrail: lasso
      mode: "pre_call"
      api_key: os.environ/LASSO_API_KEY
      api_base: "https://server.lasso.security/gateway/v3"
  - guardrail_name: "lasso-post-guard"
    openmcp_params:
      guardrail: lasso
      mode: "post_call"
      api_key: os.environ/LASSO_API_KEY
```

#### `mode` 支持的值

- `pre_call` - 在 LLM 调用**之前**运行，用于验证**用户输入**。拦截检测到策略违规（越狱、有害提示词、PII 等）的请求
- `post_call` - 在 LLM 调用**之后**运行，用于验证**模型输出**。拦截包含有害内容、策略违规或敏感信息的响应

### 2. 启动 OpenMCP 网关

```shell
openmcp --config config.yaml --detailed_debug
```

## 使用 Lasso 进行 PII 掩码

Lasso 支持使用 `/classifix` 端点进行自动 PII 检测和掩码。启用后，电子邮件、电话号码等敏感信息及其他 PII 将自动替换为适当的占位符。

### 启用 PII 掩码

要启用 PII 掩码，请将 `mask: true` 参数添加到你的护栏配置中：

```yaml showLineNumbers title="config.yaml"
model_list:
  - model_name: claude-3.5
    openmcp_params:
      model: anthropic/claude-3.5
      api_key: os.environ/ANTHROPIC_API_KEY

guardrails:
  - guardrail_name: "lasso-pre-guard-with-masking"
    openmcp_params:
      guardrail: lasso
      mode: "pre_call"
      api_key: os.environ/LASSO_API_KEY
      mask: true  # Enable PII masking
  - guardrail_name: "lasso-post-guard-with-masking"
    openmcp_params:
      guardrail: lasso
      mode: "post_call"
      api_key: os.environ/LASSO_API_KEY
      mask: true  # Enable PII masking
```

### 掩码行为

启用掩码后：

- **调用前掩码**：用户输入中的 PII 在发送给 LLM 之前被掩码
- **调用后掩码**：LLM 响应中的 PII 在返回给用户之前被掩码
- **选择性拦截**：仅拦截有害内容（越狱、仇恨言论等）；PII 违规会被掩码并允许继续

### 支持的 PII 类型

Lasso 可以检测并掩码多种类型的 PII：

- 电子邮件地址 → `<EMAIL_ADDRESS>`
- 电话号码 → `<PHONE_NUMBER>`
- 信用卡号 → `<CREDIT_CARD>`
- 社会安全号码 → `<SSN>`
- IP 地址 → `<IP_ADDRESS>`
- 以及更多基于你的 Lasso 配置的类型

## 高级配置

### 用户和会话跟踪

Lasso 允许你跟踪用户和会话，以实现更好的安全监控和上下文分析：

```yaml
guardrails:
  - guardrail_name: "lasso-guard"
    openmcp_params:
      guardrail: lasso
      mode: "pre_call"
      api_key: os.environ/LASSO_API_KEY
      lasso_user_id: os.environ/LASSO_USER_ID  # Optional: Track specific users
      lasso_conversation_id: os.environ/LASSO_CONVERSATION_ID  # Optional: Track conversation sessions
```

### 多护栏配置

你可以同时配置调用前和调用后护栏，以覆盖两个方向：

```yaml
guardrails:
  - guardrail_name: "lasso-input-guard"
    openmcp_params:
      guardrail: lasso
      mode: "pre_call"
      api_key: os.environ/LASSO_API_KEY
      lasso_user_id: os.environ/LASSO_USER_ID
      
  - guardrail_name: "lasso-output-guard"
    openmcp_params:
      guardrail: lasso
      mode: "post_call" 
      api_key: os.environ/LASSO_API_KEY
      lasso_user_id: os.environ/LASSO_USER_ID
```

### 替代配置：通用护栏 API

Lasso 也可以使用 [Generic Guardrail API](/docs/adding_provider/generic_guardrail_api) 格式进行配置：

```yaml
guardrails:
  - guardrail_name: "lasso-api-post-guard"
    openmcp_params:
      guardrail: generic_guardrail_api
      mode: post_call
      api_base: https://server.lasso.security/gateway/v3
      api_key: os.environ/LASSO_API_KEY
      additional_provider_specific_params:
        mask: false  # Set to true to enable PII masking
```

**参数：**
- **`mask`**：启用/禁用 PII 掩码的布尔标志（默认：`false`）

## 安全功能

Lasso Security 提供针对以下威胁的防护：

- **越狱尝试**：检测提示词注入和指令绕过尝试
- **有害内容**：识别色情、暴力、仇恨或非法内容的请求/响应
- **PII 检测**：发现并可以掩码个人身份信息
- **自定义策略**：执行你组织特定的内容策略
- **代码安全**：分析代码片段中的潜在安全漏洞

### 基于操作的响应控制

Lasso 护栏使用智能的基于操作的系统来决定如何处理违规：

- **`BLOCK`**：具有此操作的违规将完全拦截请求/响应
- **`AUTO_MASKING`**：违规将被掩码（如果启用了掩码），请求继续
- **`WARN`**：违规将作为警告记录，请求继续
- **混合操作**：如果任何发现具有 `BLOCK` 操作，则整个请求被拦截

这基于 Lasso 的风险评估提供细粒度控制，允许安全内容继续，同时拦截危险请求。

**示例行为：**
- 越狱尝试 → `"action": "BLOCK"` → 请求被拦截
- 检测到 PII → `"action": "AUTO_MASKING"` → 请求继续并掩码（如果启用）
- 轻微策略违规 → `"action": "WARN"` → 请求继续并记录警告日志
