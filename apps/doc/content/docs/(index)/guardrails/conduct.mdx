Conduct 护栏会在调用模型之前，把每个提示词发送到你的 Conduct 工作区。Conduct 会根据为该护栏注册所在的工具所配置的规则评估用户文本，并返回一个裁决。拦截类裁决（`block`、`approval`）会以 400 和规则 ID 拒绝该请求。非拦截类裁决（`warning`、`advisory`）会放行请求，并记录为 OpenMCP 护栏日志、spend 日志和 Admin UI 请求详情中的 `guardrail_flagged`。

该集成分装了 [`conduct-openmcp-guard`](https://pypi.org/project/conduct-openmcp-guard/) 包，因此它适用于代理会转换为护栏输入的每个端点：`/v1/chat/completions`（包括流式）、`/v1/responses` 和 `/v1/messages`。

## 快速开始

### 1. 安装插件并获取 agent 令牌

```shell
pip install "conduct-openmcp-guard>=0.2.5"
```

在 Conduct 控制台创建一个 agent 令牌；如果你的租户需要，请记下工作区 ID。该令牌会作为 bearer 凭据发送到位于 `<api_base>/mcp` 的 Conduct MCP 端点。

### 2. 将 Conduct 添加到你的 OpenMCP config.yaml

```yaml title="config.yaml"
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: conduct-guard
    openmcp_params:
      guardrail: conduct
      mode: pre_call
      default_on: true
      api_key: os.environ/CONDUCT_AGENT_TOKEN
      api_base: https://api.conductai.ai   # optional, this is the default
      workspace_id: os.environ/CONDUCT_WORKSPACE_ID   # optional
      tool_name: llm_call                  # optional, the Conduct tool your rules target
      timeout: 8                           # optional, seconds
      unreachable_fallback: fail_closed    # optional, block if Conduct cannot be reached
```

相同的字段也可以在 Admin UI 的 **Guardrails > Add Guardrail > Conduct Guard** 下配置。

### 3. 启动 OpenMCP 代理

```shell
export OPENAI_API_KEY=sk-...
export CONDUCT_AGENT_TOKEN=cond_agt_...
openmcp --config config.yaml
```

### 4. 发出你的第一个请求

被拦截的示例假定你的 Conduct 工作区中有一条设置为拦截的提示词注入规则。

## 支持的参数

`api_key` 是 Conduct agent 令牌。省略时，插件会回退到 `CONDUCT_AGENT_TOKEN` 环境变量；如果两者都未设置，则会在启动时失败。

| 参数 | 默认值 | 描述 |
|---|---|---|
| `api_base` | `https://api.conductai.ai` | Conduct API 基础 URL。MCP 端点由 `<api_base>/mcp` 推导得出。回退到 `CONDUCT_API_URL` |
| `workspace_id` | `None` | Conduct 工作区 ID，作为 `X-Workspace-Id` 请求头发送。回退到 `CONDUCT_WORKSPACE_ID` |
| `tool_name` | `llm_call` | 提示词在其下评估的 Conduct 工具名称。请与你规则所针对的工具保持一致 |
| `timeout` | `8` | Conduct 检查的超时时间（秒） |
| `unreachable_fallback` | `fail_closed` | 当 Conduct 不可达、超时或拒绝令牌时，`fail_closed` 会拒绝请求。`fail_open` 会放行 |

## 支持的模式

Conduct 只支持 `pre_call`。该插件没有响应侧的检查，因此在加载配置时 `during_call` 和 `post_call` 会被拒绝。

该插件评估请求中用户撰写的文本：`prompt`、用户消息，以及多部分用户内容中的文本部分。只出现在系统消息或工具结果中的文本不会发送给 Conduct。
