OpenMCP 通过 [Model Armor API](https://cloud.google.com/security-command-center/docs/model-armor-overview) 支持 Google Cloud Model Armor 护栏。

## 支持的护栏

- [Model Armor 模板](https://cloud.google.com/security-command-center/docs/manage-model-armor-templates) - 基于配置的模板进行内容净化和拦截

## 快速开始
### 1. 在 OpenMCP config.yaml 中定义护栏

在 `guardrails` 部分下定义你的护栏

```yaml
model_list:
  - model_name: {{openai_small}}
    openmcp_params:
      model: openai/{{openai_small}}
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: model-armor-shield
    openmcp_params:
      guardrail: model_armor
      mode: [pre_call, during_call, post_call]  # Run on input, parallel, and output
      template_id: "your-template-id"  # Required: Your Model Armor template ID
      project_id: "your-project-id"    # Your GCP project ID
      location: "us-central1"          # GCP location (default: us-central1)
      credentials: "path/to/credentials.json"  # Path to service account key
      mask_request_content: true       # Enable request content masking
      mask_response_content: true      # Enable response content masking
      fail_on_error: true             # Fail request if Model Armor errors (default: true)
      sanitize_error_detail: true     # Keep raw Model Armor responses out of errors and logs (default: true)
      default_on: true                # Run by default for all requests
```

#### `mode` 支持的值

- `pre_call` 在 LLM 调用**之前**运行，作用于**输入**
- `during_call` 与 LLM 调用**并行**运行，作用于**输入**
- `post_call` 在 LLM 调用**之后**运行，作用于**输出**

### 2. 启动 OpenMCP 网关

```shell
openmcp --config config.yaml --detailed_debug
```

### 3. 测试请求

**[Langchain、OpenAI SDK 使用示例](/docs/proxy/user_keys#request-format)**

```shell
curl -i http://localhost:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-npnwjPQciVRok5yNZgKmFQ" \
  -d '{
    "model": "{{openai_small}}",
    "messages": [
      {"role": "user", "content": "Hi, my email is test@example.com"}
    ],
    "guardrails": ["model-armor-shield"]
  }'
```

## 文档和文件扫描

自 v1.92.0 起，Model Armor 除扫描消息文本外，还会扫描内联文档附件。在 `pre_call` 和 `during_call` 时，OpenMCP 会将请求消息中的每个附件解析为字节，并在请求到达 LLM 之前将其提交给 Model Armor 的 [byte API](https://cloud.google.com/security-command-center/docs/sanitize-prompts-responses)。

OpenMCP 可识别带内联 `file_data`（base64 数据 URI 或原始 base64）的 OpenAI `type: file` 内容块，以及带内联 base64 `source` 的 Anthropic `type: document` 块。附件的 MIME 类型、声明的 `format` 或文件扩展名会映射到 Model Armor 的 `byteDataType`；PDF、Word、Excel、PowerPoint、CSV 和纯文本文档都会被扫描。byte API 不支持的类型的 inline 内容（例如图片）不会被扫描，直接通过。

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "Summarize this document"},
    {"type": "file", "file": {"file_data": "data:application/pdf;base64,JVBERi0x...", "filename": "report.pdf"}}
  ]
}
```

对文档的 Model Armor 发现始终以 HTTP 400 拦截请求：

```json
{"error": "Content blocked by Model Armor", "model_armor_response": {"sanitizationResult": {"filterMatchState": "MATCH_FOUND"}}}
```

掩码从不适用于文档。Model Armor 返回的是文档的发现结果，而不是净化后的副本，因此即使启用了 `mask_request_content`，匹配也会拦截。

### 无法扫描的附件

OpenMCP 识别为文档但无法提交扫描的附件会故障关闭（fail closed）：除非你设置 `fail_on_error: false`，否则请求会以 HTTP 400 被拦截。

| 情况 | 默认（`fail_on_error: true`） | 使用 `fail_on_error: false` 时 |
|------|--------------------------------|------------------------------|
| `file_id` 或远程 URL 引用（`http://`、`https://`、`gs://`）且无内联字节 | 被拦截 | 未扫描直接通过 |
| 大于 Model Armor 4 MB 限制的文档 | 被拦截 | 未扫描直接通过 |
| 解码失败的内联 base64 | 被拦截 | 未扫描直接通过 |
| 扫描附件时出现 Model Armor API 错误 | 被拦截 | 跳过该附件，其余附件仍会扫描 |

被拦截的请求会返回原因：

```json
{"error": "Model Armor could not scan an attachment and blocked the request: attachment of 5242880 bytes exceeds Model Armor's 4194304 byte scan limit"}
```

如果你使用 `file_id`、`gs://` 或 `http(s)://` 附件引用（Vertex AI 推荐的模式），字节永远不会到达 OpenMCP，因此 Model Armor 无法扫描它们，请求会被默认拦截。设置 `skip_unscannable_attachments: true` 可让不携带内联字节的附件未扫描直接通过，同时仍然扫描携带内联字节的附件。与 `fail_on_error: false` 不同，这会保留对真实 Model Armor API 错误（网络、配额、错误模板）的故障关闭行为；它只影响那些没有内容可发送的附件。

大于 Model Armor 4 MB 字节限制的文档确实携带字节，但超出了 byte API 可接受的范围，因此在 `fail_on_error` 下保持故障关闭；`skip_unscannable_attachments` 不覆盖它，因为那是一个真实文档，你很可能希望拦截而不是未扫描地转发。

## 支持的参数

### 通用参数

- `api_key` - str - Google Cloud 服务账号凭据（使用 ADC 时可选）
- `api_base` - str - 自定义 Model Armor API 端点（可选）
- `default_on` - bool - 是否默认运行护栏。默认为 `false`。
- `mode` - Union[str, list[str]] - 运行护栏的模式。支持的值：`pre_call`、`during_call`、`post_call`。默认为 `pre_call`。

### Model Armor 特定参数

- `template_id` - str - 你的 Model Armor 模板 ID（必需）
- `project_id` - str - Google Cloud 项目 ID（默认为凭据中的项目）
- `location` - str - Google Cloud 位置/区域。默认为 `us-central1`
- `credentials` - Union[str, dict] - 服务账号 JSON 文件路径或凭据字典
- `api_endpoint` - str - Model Armor 的自定义 API 端点（可选）
- `fail_on_error` - bool - 当 Model Armor 遇到错误（包括无法扫描的附件）时是否使请求失败（参见[文档和文件扫描](#document-and-file-scanning)）。默认为 `true`
- `skip_unscannable_attachments` - bool - 让不带内联字节的附件引用（`file_id`、`gs://`、`http(s)://`）未扫描直接通过而不是拦截，同时对真实 Model Armor API 错误保持故障关闭（参见[无法扫描的附件](#attachments-that-cannot-be-scanned)）。默认为 `false`
- `sanitize_error_detail` - bool - 将原始 Model Armor API 响应排除在面向调用方的错误详情、调试日志和护栏跟踪负载之外。默认为 `true`；设为 `false` 可恢复详细输出以便调试
- `mask_request_content` - bool - 启用请求中敏感内容的掩码。默认为 `false`
- `mask_response_content` - bool - 启用响应中敏感内容的掩码。默认为 `false`
