CrowdStrike AIDR 护栏使用可配置的检测策略来识别
并减轻 AI 应用流量中的风险，包括：

- 提示词注入攻击（有效率超过 99%）
- 50+ 种 PII 和敏感内容类型，支持自定义模式
- 毒性内容、暴力、自残以及其他不良内容
- 恶意链接、IP 和域名
- 100+ 种口语语言，支持允许列表和拒绝列表控制

所有检测结果都会被记录，用于分析、归因和事件响应。

## 前提条件

- 启用 AIDR 的 CrowdStrike Falcon 账户

  有关 CrowdStrike AIDR 功能、策略配置和高级用法的详细信息，请参阅[官方 CrowdStrike AIDR 文档](https://aidr-docs.crowdstrike.com/docs/aidr/)。

- 已安装 OpenMCP（通过 pip 或 Docker）
- 你的 LLM 提供商的 API 密钥

  要跟随本指南中的示例操作，你需要一个 OpenAI API 密钥。

## 快速开始

在 Falcon 控制台中，点击**打开菜单**（**☰**），然后进入 **AI detection and response** > **Collectors**。

### 1. 注册 OpenMCP collector

1. 在 **Collectors** 页面，点击 **+ Collector**。
1. 选择 **Gateway** 作为 collector 类型，然后选择 **OpenMCP** 并点击 **Next**。
1. 在 **Add a Collector** 界面上：
   - **Collector Name** - 为 collector 输入一个描述性名称，用于在控制台和报告中显示。
   - **Logging** - 选择是记录传入（提示词）数据和模型响应，还是只记录提交给 AIDR 的元数据。
   - **Policy**（可选）- 分配一个策略应用于传入数据和模型响应。
     - 策略可检测 AI 流量中的恶意活动、敏感数据泄露、主题违规和其他风险。
     - 未分配策略时，AIDR 会记录活动以供可见性和分析，但不会对数据应用检测规则。
1. 点击 **Save** 完成 collector 注册。

### 2. 将 CrowdStrike AIDR 添加到你的 OpenMCP config.yaml

在你的配置文件的 `guardrails` 部分定义 CrowdStrike AIDR 护栏。

```yaml title="config.yaml - Example OpenMCP configuration with CrowdStrike AIDR guardrail"
model_list:
  - model_name: {{openai_large}}                       # Alias used in API requests
    openmcp_params:
      model: openai/{{openai_small}}              # Actual model to use
      api_key: os.environ/OPENAI_API_KEY

guardrails:
  - guardrail_name: crowdstrike-aidr
    openmcp_params:
      guardrail: crowdstrike_aidr
      default_on: true                       # Enable for all requests.
      mode: []                               # Mode is required by OpenMCP but ignored by AIDR.
                                             # Guardrail always runs in [pre_call, post_call] mode.
                                             # Policy actions are defined in AIDR console.
      api_key: os.environ/CS_AIDR_TOKEN      # CrowdStrike AIDR API token
      api_base: os.environ/CS_AIDR_BASE_URL  # CrowdStrike AIDR base URL
      fail_on_error: true                    # Optional. Set false to fail open on AIDR errors (default: true)
```

## 错误处理

`fail_on_error` 控制当 AIDR guard API 无法访问或返回不可用响应时的行为。它默认为 `true`，因此护栏错误会用 HTTP 500 拦截请求。

设置 `fail_on_error: false` 则改为 fail open：连接失败、超时、4xx/5xx 响应和格式错误的回复体都会被记录，请求不受影响地继续执行。Fail-open 调用会以护栏状态 `guardrail_failed_to_respond` 记录在 spend 日志中。

```yaml title="config.yaml - CrowdStrike AIDR guardrail with fail open enabled"
guardrails:
  - guardrail_name: crowdstrike-aidr
    openmcp_params:
      guardrail: crowdstrike_aidr
      default_on: true
      mode: []
      api_key: os.environ/CS_AIDR_TOKEN
      api_base: os.environ/CS_AIDR_BASE_URL
      fail_on_error: false                   # Fail open on AIDR guard API errors
```

即使设置了 `fail_on_error: false`，以下两种情况仍然保持严格：

| 情况 | 行为 |
|------|----------|
| AIDR 在成功响应上给出拦截裁决，即使响应体的其余部分无法解析 | 请求以 HTTP 400 被拦截 |
| AIDR 返回 OpenMCP 无法解析的已转换（脱敏）响应 | 请求以 HTTP 500 失败，因此已交付的脱敏结果绝不会被丢弃 |
